# devctl: вся соцсеть одной командой

Соцсеть выросла до пяти сервисов, один из которых работает в трёх экземплярах. Поднимать их руками в нужном порядке, останавливать в обратном, а при выкате новой версии post-service
следить, чтобы пользователи ничего не заметили, надоело всем. Нужна команда `devctl`: `up` поднимает всё, `down` гасит, `restart post-service` выкатывает по одному экземпляру. Настоящие процессы и
контейнеры здесь спрятаны за типажом `Backend`, а в тестах стоит подмена с замороженным временем. Твоя часть: сама логика, то есть то, чему ты научился в задачах главы.

## Как устроено

```
         ┌─────────────────────────── Stack ───────────────────────────┐
 up ───► │ граф зависимостей ─► сервис стартует, когда готовы зависимости │ ──► Backend::start / ready
 down ─► │ обратный порядок, SIGTERM, grace, SIGKILL                     │ ──► Backend::term / exited / kill
 restart │ по экземпляру: выйти из круга, слить запросы, остановить,      │ ──► Backend::in_flight ...
         │ запустить, дождаться готовности, вернуться в круг              │
         └───────────────────────────────────────────────────────────────┘
                                    круг балансировщика: Stack::serving(service)
```

- `src/crates/devctl/src/graph.rs`: описание сервиса (`ServiceSpec`: имя, зависимости, число экземпляров), проверка графа `validate`, имена экземпляров `instances_of` (готово).
- `src/crates/devctl/src/backend.rs`: типаж `Backend` (готово).
- `src/crates/devctl/src/stack.rs`: `Stack`. Готовы вспомогательные `wait_ready` и `stop_instance`, а также вход в круг и выход из него. Нужно написать `up`, `down` и `restart`.
- `src/crates/devctl/tests/stack.rs`: приёмочные тесты. Править их нельзя, CLI восстанавливает их перед проверкой. Процессы и сеть не нужны.

## Что сделать

1. `Stack::up`: проверить граф до запуска; запускать сервис (все его экземпляры вместе), когда готовы все зависимости; независимые сервисы стартуют одновременно; готовый экземпляр входит в круг; если какой-то
   экземпляр не стал готовым за `ready_timeout`, остановить всё запущенное и вернуть `NotReady(имя экземпляра)`.
2. `Stack::down`: остановка в обратном порядке (сервис получает SIGTERM только после остановки всех зависимых от него), независимые ветки вместе; зависшие добиваются через `grace`; круги пустеют.
3. `Stack::restart(service)`: неизвестное имя это `Unknown`; экземпляры по одному: выйти из круга, дождаться доработки запросов (до `drain_timeout`), остановить, запустить, дождаться готовности, вернуться в круг.

После работы `cargo test --workspace` проходит и `cargo clippy --workspace --all-targets -- -D warnings` чист.

## Критерии приёмки

- порядок запуска следует графу, независимые сервисы стартуют одновременно, время подъёма определяется самой длинной цепочкой;
- при ошибке графа или неготовом экземпляре ничего не остаётся запущенным, круги пусты;
- остановка в обратном порядке, вежливые не добиваются, зависший добивается ровно через `grace` после SIGTERM;
- выкат post-service проходит без единой ошибки у пользователей при непрерывной нагрузке, в круге всё время не меньше двух экземпляров из трёх, остальные сервисы не затронуты;
- перезапускаемый экземпляр не получает запросов, пока не готов.

## Подсказки

Всё это ты уже писал по частям: порядок запуска и ожидание готовности (`svdep2`), остановка (`svdep3`), выкат по одному (`svdep8`). Здесь они складываются в один объект с общим кругом экземпляров.
