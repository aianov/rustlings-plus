# Репозиторий пользователей на Postgres

Соцсеть до сих пор хранила пользователей и посты в памяти: перезапустил сервис, и всё пропало.
Пора переселить их в Postgres. Остальной код не должен узнать об этом переезде, поэтому весь SQL
прячется за трейтом `UserRepository`: сервис вызывает `repo.create(...)` и не знает, что там внутри.
Ты пишешь реализацию на `sqlx` для Postgres.

## Что уже есть

- `schema.sql`: схема из двух таблиц, `users` и `posts`, с ограничениями. Имена ограничений
  (`users_username_uniq`, `users_email_uniq`, `users_username_len`, `posts_body_not_blank`) важны.
- `src/lib.rs`: типы `User`, `Post`, `NewUser`, ошибка `RepoError`, трейт `UserRepository` и функция
  `apply_schema`, которая разворачивает схему одним скриптом. Менять этот файл не нужно.
- `src/postgres.rs`: заготовка `PgUserRepository` с методами `todo!()`. Здесь вся твоя работа.
- `tests/acceptance.rs`: приёмочные тесты. Каждый тест создаёт собственную схему в Postgres курса
  (адрес из `RUSTLINGS_PG_URL`), применяет `schema.sql` и удаляет схему в конце.

## Что нужно сделать

Реализуй все методы трейта для `PgUserRepository` так, чтобы:

1. Запросы лежат в константах наверху `src/postgres.rs`, параметры передаются через `$n` и `bind`.
   Строить SQL форматированием нельзя, тест проверяет, что в файле нет `format!(`.
2. `create` вставляет пользователя и возвращает его целиком вместе со значениями, которые проставила
   база (`id`, `created_at`), одним запросом. Занятый ник даёт `RepoError::UsernameTaken`, занятая
   почта `RepoError::EmailTaken`, нарушение CHECK (слишком короткий ник) `RepoError::Invalid`.
3. Одна общая функция превращает ошибку sqlx в `RepoError`: уникальность различается по имени
   ограничения, внешний ключ (`23503`) значит `NotFound`, CHECK (`23514`) значит `Invalid`, всё
   остальное оборачивается в `RepoError::Db`. Недоступная база не должна выглядеть как `NotFound`.
4. `find_by_id` и `find_by_username` возвращают `Option`: отсутствие пользователя не ошибка.
5. `users_by_ids` берёт пользователей одним запросом, в том же порядке, что и список. Отсутствующие
   пропускаются, повторы не размножают результат, пустой список даёт пустой результат.
6. `update_bio` и `delete` возвращают `NotFound`, если пользователя нет. `None` в `update_bio`
   стирает описание (в базе должен стать NULL). Посты удалённого пользователя уходят вместе с ним:
   это уже делает схема.
7. `add_post` добавляет пост и возвращает его целиком. Несуществующий автор это `NotFound`,
   пустой текст `Invalid`.
8. `posts_of` отдаёт посты автора страницей: сначала новые, при равной дате больший `id` раньше, чтобы
   страницы не пересекались и не теряли строки.
9. `register_with_first_post` создаёт пользователя и его первый пост одной транзакцией: если не
   получился хотя бы один из двух шагов, не остаётся ничего.
10. Параллельные регистрации одного ника дают ровно один успех, остальные `UsernameTaken`, без
    предварительных SELECT.

## Критерии приёмки

`cargo test` в корне проекта: все тесты из `tests/acceptance.rs` проходят. Они проверяют значения,
проставленные базой, перевод ошибок, порядок и страницы, откат транзакции, гонку за ник и отсутствие
`format!` в SQL.

## Структура

```
sqlx_user_repo/
  Cargo.toml
  schema.sql
  src/lib.rs          типы, трейт, apply_schema (готово)
  src/postgres.rs     PgUserRepository (твоя работа)
  tests/acceptance.rs приёмочные тесты (не менять)
```

## Как запускать

Postgres курса должен работать (`docker compose up -d` в папке курса). Потом `cargo test`.

## Подсказки по теории

Все приёмы есть в README главы: `query_as` с `RETURNING`, `fetch_optional`, `rows_affected`,
`= ANY($1)` с `array_position`, `From<sqlx::Error>` и `constraint()`, `pool.begin()` и `&mut *tx`.
Для `register_with_first_post` оба запроса пишутся на `&mut *tx`, а `commit` идёт в самом конце.
