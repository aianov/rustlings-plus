# ntls9: договариваемся о протоколе

Один порт, на котором сидят и клиенты HTTP/1.1, и клиенты HTTP/2 (gRPC). Как сервер узнаёт, на каком языке с ним собираются говорить? В открытом TCP никак, надо угадывать по первым байтам. В TLS для этого есть расширение **ALPN**:
клиент в ClientHello перечисляет протоколы, которые умеет, сервер выбирает один и называет его в ответе. Поэтому браузеры и gRPC-клиенты открывают HTTP/2 только после того, как сервер сказал «h2» в рукопожатии.

## Что сделать

В `src/lib.rs`:

1. `server_config(cert_pem, key_pem)`: сервер предпочитает `h2`, потом `http/1.1`.
2. `client_config(ca_pem, offer)`: клиент доверяет одному CA и предлагает протоколы из `offer` в этом порядке (список может быть пустым: тогда расширения ALPN нет вообще).
3. `negotiate(addr, name, ca_pem, offer)`: подключается, делает рукопожатие и возвращает договорённый протокол как строку (`None`, если стороны ни о чём не договаривались).

## Критерии приёмки

`cargo test`: клиент `h2, http/1.1` получает `h2`; клиент `http/1.1` получает `http/1.1`; клиент `http/1.1, h2` получает `h2`, потому что выбирает сервер; клиент без ALPN подключается, и договорённого протокола нет;
клиент с чужим протоколом (`spdy/3`) получает отказ рукопожатия. Сервер видит тот же итог, что и клиент.

## Подсказки по теории

Протокол в ALPN это байтовая строка, `b"h2"` или `b"http/1.1"`. У `ServerConfig` и `ClientConfig` есть публичное поле `alpn_protocols: Vec<Vec<u8>>`. Результат переговоров читают у уже установленного соединения.
Если сервер настроил ALPN, а клиент прислал список без общих протоколов, rustls прерывает рукопожатие: продолжать без договорённости значило бы говорить на разных языках.
