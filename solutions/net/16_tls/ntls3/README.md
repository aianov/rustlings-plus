# ntls3: эхо-сервер с шифрованием

TCP-сервер из первых глав получает шифрование почти даром: между `accept` и обработкой соединения добавляется рукопожатие, и дальше обработчик читает и пишет в `TlsStream` так же, как раньше в `TcpStream`. Тонкости не в шифровании, а в рукопожатии:
оно идёт по сети и занимает время, а клиент может быть медленным, злым или просто не говорить по TLS.

## Что сделать

В `src/lib.rs` функция `serve(listener, config, handshake_timeout)` принимает соединения до отмены и для каждого:

1. выполняет TLS-рукопожатие с ограничением по времени `handshake_timeout`;
2. если рукопожатие удалось, отвечает эхом: всё, что клиент прислал, отправляет обратно, пока клиент не закроет свою сторону, потом корректно закрывает TLS (`shutdown`);
3. если не удалось (чужой протокол, обрыв, истёк срок), просто закрывает соединение, ничего не паникуя и не влияя на остальные соединения.

Главное требование: молчащий или медленный клиент не должен мешать остальным.

## Критерии приёмки

`cargo test`: клиент получает эхо по TLS; клиент, подключившийся и молчащий, не мешает другим и сам отбрасывается после срока; клиент, говорящий не по TLS, отбрасывается, а следующий нормальный клиент обслуживается; клиент с недоверенным сертификатом
не роняет сервер.

## Подсказки по теории

`TlsAcceptor::from(Arc<ServerConfig>)` превращает сырой поток в TLS-поток вызовом `accept(stream).await`. Настройки конфигурации `Arc`, поэтому её дёшево раздавать задачам. Закрывать TLS нужно через `shutdown()`:
он отправляет `close_notify`, по которому собеседник отличает честное завершение от обрыва соединения злоумышленником.
