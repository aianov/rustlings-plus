# nfz_harness: крейт minifuzz

Проверочная задача главы. Ты собираешь свой маленький инструментарий для проверки парсеров из того, что
писал в задачах: генератор случайных чисел, мутатор, фаззер с бюджетом, сжатие падающего входа,
запуск свойств и проверка разрезов. Потом этим инструментом будут проверяться HTTP и WebSocket
парсеры курса, поэтому крейт должен быть без зависимостей.

## Что уже есть

Крейт `minifuzz` со всеми типами и сигнатурами, тела падают через `todo!()`. Приёмочные тесты в
`tests/acceptance.rs` (не править). Планируемые баги в тестах «посажены» в маленьких целях, сам крейт
ничего про них не знает.

## Что сделать

1. `Rng` (splitmix64): `new`, `next_u64`, `below` (без перекоса), `range`, `chance`, `pick`.
2. `mutate(rng, input, corpus)` (1..3 раунда: бит, байт, вставка, удаление, дубль куска, кусок из corpus,
   «интересные» значения из `INTERESTING`), `shrink(input, still_fails)` (убирает большие куски, потом
   всё меньше, затем упрощает байты до `a`).
3. `input_for(corpus, seed, iteration)` и `fuzz(&Config, corpus, target)`: итерация выводится из
   `seed + номер`, паника цели ловится, вход сжимается `shrink`, результат это `Crash { input, original,
   iteration, message }`. Остановка по числу итераций или по времени (`max_time`): бюджет проверяется перед каждой итерацией, а зависший вызов цели не прерывается
   (это работа таймаута уровнем выше).
4. `run_property(cases, base_seed, prop)`: останавливается на первом сбое, отдаёт `PropFailure { seed,
   message }`.
5. `check_splits(input, run)`: результат на целом входе против результата на каждом разрезе на два кусочка,
   а потом при побайтовой подаче; первый расклад, который расходится, возвращается как `SplitFailure`.

## Критерии приёмки

`cargo test`. Проверяется:

- первые три числа splitmix64 с seed 0, детерминизм, границы `below`, `range`, `chance`;
- мутатор детерминирован и почти всегда что-то меняет, на пустом входе не падает;
- `shrink` на 100000 байтах делает меньше 1500 проверок и справляется с предикатом «чётная длина»;
- фаззер находит посаженную ошибку и сжимает вход до двух байтов `FF 0A`, вход итерации восстанавливается;
- бюджеты по итерациям и по времени соблюдаются;
- `run_property` и `check_splits` находят нарушение и сообщают, где оно.

## Подсказки

Каждый кусок уже был задачей главы (nfz1, nfz3, nfz5, nfz6, nfz7, nfz8). Соберите их в один крейт и сделайте
публичными. Для времени используй `std::time::Instant`. Цель фаззера не обязана быть `UnwindSafe`:
оберни вызов в `AssertUnwindSafe`.
