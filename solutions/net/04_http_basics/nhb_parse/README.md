# nhb_parse: крейт http-parse

Проверочная задача главы. Ты собираешь из кусочков главы крейт, на котором потом вырастет
сервер: разбор запросов из потока байтов и сборка ответов. Сервера здесь ещё нет: только чистые
функции над байтами, никакой сети и никаких зависимостей.

## Что уже есть

Крейт `http-parse` со всеми типами и сигнатурами. `Limits` с разумными значениями по умолчанию
и `ParseError` готовы, остальное падает через `todo!()`. Приёмочные тесты лежат в
`tests/acceptance.rs` (не править, CLI восстановит файл).

## Что сделать

1. `Method` (`as_str`, `FromStr`) и `Headers`: поиск без учёта регистра, повторные имена, порядок и
   исходный вид имён сохраняются.
2. `parse_request(buf, &limits)` разбирает запрос из накопленного буфера:
   - `Ok(Parsed::Partial)`, пока запрос не пришёл целиком; `Complete { request, consumed }`, когда пришёл.
     `consumed` это только байты этого запроса, остаток может быть следующим;
   - строка запроса: ровно три части через один пробел, метод в верхнем регистре, версия HTTP/1.0 или 1.1,
     цель начинается с `/` (иначе `BadTarget`);
   - заголовки: `Имя: значение`, пробел перед двоеточием и управляющие символы запрещены, не UTF-8 это `BadHeader`;
   - в HTTP/1.1 нужен ровно один непустой `Host` (`MissingHost`, `DuplicateHost`);
   - тело: `Content-Length` (только цифры; разные значения это `Smuggling`; плохое число это `BadContentLength`) либо
     `Transfer-Encoding: chunked` (с трейлерами). Оба сразу это `Smuggling`;
   - лимиты `Limits` срабатывают раньше, чем придут данные: голова, которая уже не поместится
     (`HeadTooLarge`), больше `max_headers` заголовков, тело больше `max_body` по заявленной длине.
3. `Request::path()` (раскодированный путь, плюс остаётся плюсом), `query()` (пары, раскодированные после
   разбиения, плюс это пробел) и `keep_alive()` по версии и заголовку `Connection`.
4. `StatusCode` (диапазон 100..=599, причина, правило про тело) и `Response`: `header` отвергает CR, LF и
   прочие управляющие символы в значении и плохие имена; `to_bytes(head_only)` ставит `Content-Length` сам,
   не пишет тело там, где его быть не может, и на HEAD пишет длину без тела.

## Критерии приёмки

`cargo test`. Проверяется:

- простой GET, POST с телом, содержащим пустую строку, chunked-запрос с трейлерами;
- каждый префикс каждого запроса даёт `Partial`;
- три запроса подряд плюс обрезанный четвёртый;
- путь и запрос, ошибки в строке запроса и заголовках, правила Host и keep-alive;
- контрабанда запросов и расщепление ответа отвергаются;
- лимиты срабатывают без ожидания тела;
- парсер не паникует на трёх тысячах случайных и искажённых входов.

## Подсказки

Берись за задачи главы по порядку, каждая задача это готовый кусок: `percent_decode` (nhb4),
`parse_header_line` (nhb6), `head_end` (nhb8), `content_length` (nhb10), `decode_chunked` (nhb11),
`check_host` и `keep_alive` (nhb13), сборка ответа (nhb15, nhb16). Сначала проверь, что каждая часть
по отдельности проходит свои тесты, потом склей их в `parse_request`. Все ошибки головы нужно
выдавать, как только голова пришла целиком, а не после тела.
