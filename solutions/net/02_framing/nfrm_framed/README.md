# nfrm_framed: свой Framed

Все протоколы дальше (HTTP, WebSocket, gRPC) держатся на одном приёме: между сокетом и
прикладным кодом стоит слой, который превращает поток байтов в сообщения и обратно. В tokio-util
он называется `Framed`. Здесь ты пишешь его сам, вместе с двумя кодеками: строки и кадры с длиной.

## Что уже есть

Крейт `framing` с файлами в `src/`:

- `codec.rs`: трейты `Decoder` и `Encoder` (готовы, в том числе `decode_eof`);
- `lines.rs` и `length.rs`: типы ошибок и заготовки кодеков `LinesCodec` и `LengthCodec`;
- `framed.rs`: структура `Framed<S, C>` и заготовки `recv` и `send`;
- `lib.rs`: перечень публичных имён (менять не нужно).

Приёмочные тесты лежат в `tests/acceptance.rs`, их править не нужно.

## Что сделать

1. `LinesCodec::new(max_len)`: сообщение это строка (тип `String`) до `\n`, без `\n` и без `\r` перед
   ним. Длиннее `max_len` это `LinesError::TooLong`, и этот отказ должен приходить, как только
   накоплено больше лимита, не дожидаясь `\n`. Не UTF-8 это `BadUtf8`. При записи `\n` дописывается,
   строка длиннее лимита это `TooLong`.
2. `LengthCodec::new(max_len)`: сообщение это `Vec<u8>`. Кадр: четыре байта длины (u32 big-endian), потом
   тело. Длина больше лимита это `LengthError::TooLong` сразу по заголовку. При записи то же правило.
3. `Framed::recv()`: вернуть следующее сообщение. Буфер накопления живёт внутри `Framed`,
   сообщения, пришедшие вместе, выдаются по одному, при неполном сообщении читается сокет.
   Чистый конец потока это `Ok(None)` (и все последующие вызовы тоже), обрыв посреди сообщения это
   ошибка. `recv` должен быть безопасен к отмене: если его вызов прервали по таймауту, уже
   прочитанные байты не теряются.
4. `Framed::send(item)`: закодировать сообщение и отправить его одной записью в сокет.

## Критерии приёмки

`cargo test`. Тесты проверяют круговой обмен для обоих кодеков, склейку и дробление, доставку по
одному байту, чистый и оборванный конец, лимиты, безопасность `recv` к отмене по таймауту,
одну запись на сообщение и возврат непрочитанных байтов через `into_parts`.

## Структура

```
nfrm_framed/

  src/lib.rs codec.rs lines.rs length.rs framed.rs
  tests/acceptance.rs   приёмочные тесты (не править)
```

## Подсказки

Кодек ничего не знает про сокет: он получает `&mut BytesMut` и возвращает `Ok(None)`, пока
сообщение не пришло целиком (и тогда не трогает буфер). Всё остальное делает `Framed`: цикл
«попробуй декодировать, иначе дочитай в буфер через `read_buf`». Сначала напиши кодеки (их можно
проверять без сети, как в `nfrm12`), потом `Framed`.
