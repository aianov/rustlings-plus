# ntx_tower_layer: журнал каждого вызова

Хочется одну строку в журнале на каждый вызов: идентификатор запроса, метод, код ответа, сколько заняло. Перехватчик тут не поможет:
он видит запрос, но не ответ, и не знает, сколько времени всё это заняло. Нужен слой **tower** (`Layer`), который оборачивает сервис целиком
и видит HTTP-запрос и HTTP-ответ.

## Что сделать

В `src/lib.rs` готовы `LogLayer` и `LogService`, нужно написать `call`: что происходит с каждым запросом. В `LogLine` попадают:

- `request_id`: заголовок `x-request-id` запроса или `-`, если его нет;
- `path`: путь метода (`/users.v1.Users/GetUser`);
- `status`: код gRPC. Для ошибок он лежит в заголовках ответа (`grpc-status`), для успешных ответов в заголовках его нет, считай `0`;
- `elapsed`: время от начала вызова до готовности ответа (в нём вместе с обработчиком).

Слой не меняет ни запрос, ни ответ и не должен ломать параллельные вызовы.

## Критерии приёмки

`cargo test`: настоящий сервер со слоем и настоящий клиент. Для успешного вызова строка с правильным путём, идентификатором и временем,
не меньшим времени обработчика. Для ошибки код ответа в строке. Двадцать параллельных вызовов дают двадцать строк с их идентификаторами.
Клиент получает те же ответы, что и без слоя.

## Подсказки по теории

Сервис tower это `poll_ready` («готов принять запрос?») и `call` (принять запрос и вернуть будущее ответа). Слой оборачивает один сервис в другой.
Главное неудобство: `call(&mut self)` возвращает будущее, которое живёт дольше вызова, поэтому внутрь будущего нужно перенести **копию**
внутреннего сервиса, а не ссылку на `self`. Стандартная идиома (она нужна, чтобы `poll_ready` внутреннего сервиса относился к той же копии,
которую вызываем):

```rust
let clone = self.inner.clone();
let mut inner = std::mem::replace(&mut self.inner, clone);
```
