# ntx_client_interceptor: токен в каждом вызове

Шлюз ходит к соседним сервисам от имени пользователя и должен класть токен в заголовок `authorization` каждого вызова. Писать это
руками у каждого вызова значит рано или поздно забыть один. Для таких вещей есть **перехватчик клиента** (`Interceptor`): функция,
которая видит каждый исходящий запрос и может изменить его метаданные.

## Что сделать

В `src/lib.rs` перехватчик `TokenInterceptor` держит общий токен (`Arc<RwLock<String>>`: его обновляют, когда токен перевыпущен).
Допиши `Interceptor::call`:

1. Если в запросе уже есть `authorization`, оставь как есть: вызывающий мог задать свой токен для одного вызова.
2. Иначе возьми **текущее** значение общего токена и положи в `authorization: Bearer <токен>`. Токен перевыпущен между двумя вызовами,
   значит второй вызов должен уехать уже с новым.
3. Пустой токен означает «аноним»: заголовка нет.
4. Токен с недопустимыми для заголовка символами (перевод строки и тому подобное) не должен паниковать: вызов заканчивается ошибкой
   `Unauthenticated` ещё до отправки.

## Критерии приёмки

`cargo test`: поддельный сервер записывает `authorization` каждого вызова; токен виден на сервере; обновлённый токен подхватывается
без пересоздания клиента; явный заголовок не перетирается; плохой токен даёт `Unauthenticated`, и сервер ничего не получает.

## Подсказки по теории

Перехватчик синхронный: он получает `Request<()>` (тело ещё не разобрано, только метаданные и расширения), возвращает его же или
`Err(Status)`. Асинхронной работы внутри нет, поэтому токен должен лежать готовым, а обновлять его будет другая задача. Ответ
перехватчик не видит вообще: для этого нужен слой tower (следующая задача).
