# ntx_health: сервис готов?

Контейнер запущен, процесс жив, но сервис ещё прогревает кеш или потерял связь с базой. Балансировщик, который смотрит только на «порт открыт», отправит ему
трафик. Договорённость для таких случаев стандартная, это протокол **gRPC Health Checking**: у сервера есть сервис `grpc.health.v1.Health`
с методом `Check`, который отвечает `SERVING`, `NOT_SERVING` или `SERVICE_UNKNOWN` для заданного имени сервиса. Для tonic готовый крейт `tonic-health`.

## Что сделать

В `src/lib.rs` сервис пользователей без интересной логики и три функции вокруг здоровья:

1. `serve(listener, initial)`: запускает сервер, на котором работают `users.v1.Users` и сервис здоровья. Начальное состояние `users.v1.Users` задаёт `initial`.
   Возвращает `HealthReporter` (им состояние потом меняют) и `JoinHandle` сервера;
2. `status_of(channel, service)`: спрашивает у сервера состояние сервиса с таким именем и отдаёт `Observed` (то, что пришло по сети). Неизвестное имя это ошибка `NotFound`;
3. `wait_serving(channel, service, timeout)`: так шлюз ждёт при старте, пока сосед будет готов. Опрашивает раз в 50 мс до `SERVING`,
   переживает ошибки (сосед может ещё не слушать порт), по истечении `timeout` возвращает `DeadlineExceeded`.

## Критерии приёмки

`cargo test`: сервис, начавший с `NOT_SERVING`, переходит в `SERVING`, и `wait_serving` это замечает; сервис, который не станет готовым, даёт
`DeadlineExceeded` без зависания; сосед, который вообще не слушал порт в начале, но поднялся позже, тоже дожидается.

## Подсказки по теории

`tonic_health::server::health_reporter()` возвращает пару: управляющий объект (`HealthReporter`, клонируется) и готовый сервис для `add_service`. Состояние
конкретного сервиса меняют методом `set_service_status(имя, статус)`. Пустое имя `""` означает «сервер в целом».

Внимание: в `tonic-health` два перечисления с одним именем `ServingStatus`. Одно (`tonic_health::ServingStatus`) используется на стороне сервера, им задают состояние. Другое
(`tonic_health::pb::health_check_response::ServingStatus`) это то, что приходит по сети в ответе клиенту, в заготовке оно переименовано в `Observed`. Типы разные, сравнивать их друг с другом нельзя.
