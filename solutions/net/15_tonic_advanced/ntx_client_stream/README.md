# ntx_client_stream: лайки пачкой

Мобильное приложение накопило лайки без сети и теперь отправляет их все сразу. Слать по вызову на каждый лайк дорого, одним огромным
сообщением опасно (лимит размера, память). Подходит **client streaming**: клиент открывает один вызов, шлёт в него сколько нужно сообщений
и в конце получает один ответ. Сервер читает входящий поток по одному сообщению.

Тонкость в том, что значит «поток кончился». Клиент, закрывший свою сторону, и клиент, у которого оборвали вызов (закрыли приложение, истёк срок), выглядят для
сервера одинаково: `Ok(None)` из `message()`. Различить их нечем. Поэтому в протоколе, где пачку нужно применить целиком или не применять вовсе, клиент подтверждает
конец явно: последним сообщением `Commit`.

## Что сделать

В `src/lib.rs`:

1. `Likes::send_batch` (сервер): читает поток `LikeRequest` и считает лайки по постам.
   - `post_id` равен 0: `InvalidArgument`;
   - больше `MAX_BATCH` (1000) лайков в одном вызове: `ResourceExhausted`, причём читать остаток потока не нужно;
   - пришёл `Commit`: пачка закончена, остальное не читаем;
   - поток кончился без `Commit`: `Aborted`, потому что клиент мог оборваться на середине;
   - **всё или ничего**: в хранилище попадает результат только пачки, дочитанной до `Commit` без ошибок.
   - ответ: сколько лайков принято и на скольких разных постах.
2. `send_likes(client, ids)`: отправляет список идентификаторов постов потоком, в конце `Commit`, и возвращает итог.

## Критерии приёмки

`cargo test`: итог посчитан верно; ошибка посреди потока не оставляет ничего в хранилище; 1001 лайк даёт `ResourceExhausted`; бесконечный поток
не зависает сервер; поток без `Commit` и клиент, оборвавший вызов посреди пачки, ничего не записывают.

## Подсказки по теории

Входящий поток в обработчике это `Streaming<T>`: метод `message().await` возвращает `Ok(Some(m))`, пока клиент шлёт, и `Ok(None)`, когда клиент закрыл свою
сторону; ошибка транспорта приходит как `Err(Status)`. Исходящий поток на клиенте: любой `Stream` с нужным типом элементов, например `tokio_stream::iter(..)`.
Сообщение с `oneof` в prost превращается в структуру с полем `kind: Option<like_request::Kind>`.
