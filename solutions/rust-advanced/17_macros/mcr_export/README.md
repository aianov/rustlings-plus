# Проект: макросы между крейтами

Проверки данных в соцсети повторяются в каждом сервисе: логин непустой, возраст в разумных пределах. Их
оформили макросами в отдельном крейте `social-macros`, чтобы сервисы не копировали код. У автора всё
работало, пока макросы лежали в том же крейте. Как только их подключил `feed-app` (лежит рядом и менять его
нельзя), сборка рассыпалась. Нужно починить `social-macros`.

## Что есть

- `crates/social-macros/src/lib.rs`: крейт с двумя макросами. `require!(условие, "поле", "причина")` выходит из
  функции с `Err(Invalid { .. })`. `valid_login!(выражение)` проверяет логин и возвращает `Result<String, Invalid>`;
  внутри себя он использует `require!`.
- `crates/feed-app`: сервис, который подключает оба макроса (`use social_macros::{require, valid_login};`),
  а в одном месте зовёт макрос по полному пути `social_macros::require!`.

## Что нужно сделать

Поправить только `crates/social-macros/src/lib.rs`, чтобы `cargo test --workspace` проходил.

1. Макросы должны быть доступны другим крейтам по имени крейта и через `use`.
2. Макросы должны работать там, где ничего лишнего не импортировано и где в области видимости есть чужие
   типы с теми же именами.
3. Публичным остаётся только то, что нужно пользователям: сами макросы и скрытый служебный модуль
   `__private` (с `#[doc(hidden)]`), через который макросы ссылаются на тип ошибки `Invalid` и функцию проверки
   логина. Модули `errors` и `validate` публичными не становятся.
4. Тип `Invalid { field, reason }` пользователь видит как `social_macros::Invalid`.

## Как проверить

```
cargo test --workspace
```

Приёмочные тесты лежат в `crates/feed-app/tests/acceptance.rs`, их менять нельзя.
