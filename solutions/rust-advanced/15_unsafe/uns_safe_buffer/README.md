# Проект: кольцевой буфер байтов

Шлюз чата принимает байты из сокета кусками и отдаёт разборщику сообщений. Между ними нужен буфер: пишущий
кладёт, читающий забирает, ничего не копируется лишний раз и память не растёт. Классика для этого кольцевой
буфер: массив фиксированного размера, где конец «замыкается» на начало. Ты пишешь такой буфер с `unsafe`
внутри (прямые копирования и срезы из сырых указателей) и безопасным API снаружи. Только `std`.

## Что нужно сделать

В `crates/byte-ring/src/lib.rs` объявлены типы и сигнатуры, тела пустые. Поля структуры добавь сам.

1. `ByteRing::with_capacity(n)`: буфер на `n` байт. `n == 0` допустим, такой буфер всегда пуст и всегда полон.
   Память выдели сам (`std::alloc::alloc` и `Layout`, либо `Box<[MaybeUninit<u8>]>`), хранить можно `NonNull<u8>`.
   Память освобождается в `Drop` ровно один раз. Нельзя читать не записанные байты.
2. `capacity`, `len`, `is_empty`, `is_full`.
3. `push(byte)`: `Err(Full)`, если места нет. `pop()` и `peek()` работают с самым старым байтом.
4. `write(data)` кладёт сколько влезет и возвращает число записанных байт (может быть меньше `data.len()`).
   `read(out)` забирает сколько есть, не больше `out.len()`, и возвращает число. Запись и чтение через
   границу кольца идут двумя копированиями (`ptr::copy_nonoverlapping`), а не побайтово.
5. `as_slices()` возвращает содержимое по порядку как два среза без копирования: если данные не перешагнули
   границу кольца, второй срез пустой. Если первый пуст, второй тоже.
6. `discard(n)` выбрасывает до `n` самых старых байт и возвращает сколько выбросил, `clear()` опустошает.
7. Тип можно переносить в другой поток (`Send`). Раз внутри сырой указатель, это придётся пообещать самому.
8. Безопасность: ни один публичный метод не `unsafe`, у каждого `unsafe`-блока и `unsafe impl` комментарий
   `// SAFETY:` с обоснованием, у каждой `unsafe fn` (если заведёшь приватную) раздел `# Safety`.
   Никаких `static mut` и `transmute`.

## Как проверить

```
cargo test --workspace
```

Приёмочные тесты лежат в `crates/byte-ring/tests/acceptance.rs`, их менять нельзя. Среди них случайный прогон
тысяч операций против обычного `VecDeque`: любая ошибка на стыке кольца там всплывёт.
