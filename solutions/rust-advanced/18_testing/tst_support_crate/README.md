# Проект: фейки, которые не попадут в релиз

В воркспейсе три крейта: `contracts` (трейты `Clock` и `Ids`), `shop-core` (заказы) и `test-support`
(подставные часы и генератор номеров для тестов). Тесты ядра работают, но настройка сломана двояко. Крейт
`test-support` записан у `shop-core` как обычная зависимость, значит, подставные часы уезжают в рабочую
сборку. А сами фейки в `test-support` доступны всегда, хотя должны включаться только по просьбе тестов.

## Что нужно сделать

1. Сделай так, чтобы `test-support` не входил в обычные зависимости `shop-core`, но тесты ядра по-прежнему
   его видели.
2. Спрячь `FakeClock` и `SeqIds` в `test-support` за feature `test-util`. По умолчанию feature выключена.
   Функция `unique_name` нужна всегда и от feature не зависит.
3. Ядро включает `test-util` само, в той же строке, где объявляет `test-support` для тестов.
4. `cargo test --workspace` проходит, тестов ядра три.

## Как проверить

```
cargo test --manifest-path acceptance/Cargo.toml
```

Руками полезно посмотреть `cargo tree -p shop-core -e normal` (что тянет рабочая сборка) и
`cargo tree -p shop-core -e dev` (что добавляют тесты). Приёмочные тесты в `acceptance/` менять нельзя.
