# Проект: тесты снаружи для почтового ящика

Крейт `inbox` это ящик входящих сообщений для нашей соцсети: принимает сообщения, помечает прочитанными,
ищет и чистит. Код готов и работает, а тестов нет совсем. Юнит-тесты у приватного помощника `normalize`
были бы уместны внутри, но сейчас нужны другие: те, что видят крейт так же, как его видят остальные
крейты проекта, то есть только через публичный API.

## Что нужно сделать

1. Создай папку `crates/inbox/tests/` и положи в неё не меньше двух файлов с тестами. Каждый файл это
   отдельный тестовый крейт, в каждом не меньше двух тестов.
2. Общие помощники (готовый ящик с N сообщениями, строка нужной длины) вынеси в `tests/common/mod.rs`
   и подключи в обоих файлах строкой `mod common;`. Не называй его `tests/common.rs`: cargo соберёт такой
   файл как ещё один тестовый крейт, и в выводе появится пустой запуск `running 0 tests`.
3. Помощники должны быть `pub`, иначе тестовые файлы их не увидят. Каждый файл пользуется помощниками не
   целиком, поэтому компилятор будет жаловаться на неиспользуемое. Сборка тестов должна идти без единого
   предупреждения.
4. Один тест (самый долгий: десятки тысяч сообщений) пометь `#[ignore = "причина"]`. Обычный `cargo test`
   его пропускает, а `cargo test -- --ignored` обязан проходить.
5. Тесты должны ловить ошибки в `crates/inbox/src/lib.rs`: приёмка по очереди подменяет в коде девять
   правильных строк на неправильные (граница длины, номера, регистр поиска, потеря отправителя и так
   далее), и на каждой подмене набор тестов обязан покраснеть. Свой код библиотеки менять нельзя.

## Правила работы ящика

Номера сообщений идут с 1. Текст перед сохранением очищается: любые пробельные символы подряд превращаются
в один пробел, края обрезаются. Пустой после очистки текст это `Empty`. Длина считается в символах, предел
`MAX_LEN` включительно, длиннее это `TooLong(длина)`. `mark_read` на неизвестный номер возвращает
`NotFound(номер)`. `clear_read` удаляет прочитанные и возвращает, сколько удалено. `search` ищет подстроку
без учёта регистра.

## Как проверить

```
cargo test --manifest-path acceptance/Cargo.toml
```

Для своей работы удобнее `cargo test -p inbox`, а для полезных режимов: `cargo test -p inbox mark_read`
(фильтр по имени), `-- --nocapture` (показать вывод `println!` в тестах), `-- --ignored` (запустить
отложенные). Приёмочные тесты лежат в `acceptance/`, менять их нельзя.
