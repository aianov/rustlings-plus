# Мини-рантайм

Ты прочитал, как устроен tokio: очередь готовых задач, `Waker`, который кладёт задачу обратно в
очередь, драйвер времени, `JoinHandle` с общим слотом, парковка потока, когда делать нечего. Теперь
сложи это в одну работающую вещь. Рантайм однопоточный и маленький, но настоящий: на нём идут
`spawn`, `sleep`, `yield_now`, ждущие друг друга задачи и будильники из чужих потоков.

В `crates/minirt/src/lib.rs` объявлены `Runtime`, `JoinHandle`, `Sleep`, `YieldNow` и функции.
Тела заменены на `todo!()`, поля у структур придумываешь ты, внешние сигнатуры не меняй.

## Что нужно сделать

1. **Запуск.** `Runtime::block_on(future)` гоняет главное future и все порождённые задачи на
   вызвавшем потоке и возвращает результат главного. Как только главное готово, `block_on`
   возвращается, даже если другие задачи не закончили (так же делает tokio).
2. **Задачи.** `Runtime::spawn` и свободная функция `spawn` (внутри `block_on`) принимают любое
   `'static` future без требования `Send` и возвращают `JoinHandle`. Задачи стартуют в порядке
   создания. Вне `block_on` свободные `spawn`, `sleep`, `now` паникуют.
3. **Очередь и Waker.** Готовые к опросу задачи стоят в одной очереди. `Waker` задачи ставит её в
   конец очереди и должен работать из любого потока: чужой поток может разбудить спящий рантайм.
   `yield_now().await` отдаёт ход и встаёт в конец очереди, так что задачи ходят по кругу.
4. **JoinHandle.** Это future с результатом задачи. Результат лежит в общем слоте, ждущий оставляет
   там свой `Waker`. Выброшенный handle задачу не отменяет.
5. **Время.** `Runtime::new()` работает по настоящим часам, `Runtime::paused()` по условным: когда
   готовых задач нет, часы прыгают сразу к ближайшему сроку (как `start_paused` в tokio). Сроки
   хранятся в одной структуре, упорядоченной по времени; равные сроки будятся в порядке
   создания. `sleep(d)` кладёт туда `Waker` на `now() + d`; повторный опрос обновляет `Waker`;
   выброшенный `Sleep` снимает свой срок (`live_timers()` считает живые).
6. **Сон.** Когда готовых задач нет, поток не крутится вхолостую: настоящие часы ждут до
   ближайшего срока (`park_timeout`), а без сроков до пробуждения (`park`). Часы с паузой без
   сроков тоже ждут пробуждения.
7. `Runtime::elapsed()` и `now()` дают время с создания рантайма: у условных часов это условное
   время, у настоящих реальное.

## Критерии приёмки

`cargo test --workspace` в корне проекта: все тесты `crates/acceptance/tests/acceptance.rs`
проходят. Они проверяют порядок задач и круговую очередь, точные моменты пробуждения на условных
часах, параллельность снов, выброшенные `JoinHandle` и `Sleep`, пробуждение из чужого потока,
десять тысяч задач и паники вне рантайма. Каждый сценарий обёрнут сторожем: зависший рантайм даёт
ошибку через несколько секунд, а не вечное ожидание. Решение должно проходить
`cargo clippy --workspace --all-targets -- -D warnings`.
