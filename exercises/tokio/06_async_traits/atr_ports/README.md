# Порты соцсети

Наша соцсеть растёт, и хранилища пора прятать. Сегодня пользователи и посты живут в памяти, завтра
переедут в базу, послезавтра часть уйдёт во внешний сервис. Остальной код не должен заметить ни одного
переезда, поэтому сервис общается с хранилищами через трейты-порты и держит их как `Arc<dyn …>`.
Эту прослойку ты и пишешь.

## Что уже есть

Рабочая папка это воркспейс из двух крейтов:

```
atr_ports/
  Cargo.toml
  crates/
    ports/              трейты-порты, сервис, таблица команд
      src/lib.rs
    memory/             реализации портов: в памяти и «медленные»
      src/lib.rs
      tests/acceptance.rs     приёмочные тесты (менять нельзя)
```

В `crates/ports/src/lib.rs` лежат типы (`User`, `Post`, `RepoError`, `Response`), объявления трейтов
`UserRepo` и `PostRepo` и заготовки `Service` и `Commands`. В `crates/memory/src/lib.rs` заготовки
четырёх реализаций. Сейчас проект не собирается: сервис держит `Arc<dyn UserRepo>`, а трейты написаны
так, что `dyn` невозможен. С этого и начни.

## Что нужно сделать

1. **Трейты.** `UserRepo` и `PostRepo` должны работать за `dyn` и быть `Send + Sync`, а их future
   обязаны быть `Send`. Методы остаются прежними по смыслу (имена и аргументы смотри в заготовке),
   но возвращают они теперь упакованные future.
2. **`MemUsers`** хранит пользователей в памяти. `create` выдаёт id подряд, начиная с 1; занятое имя
   даёт `RepoError::Conflict` и ничего не меняет. `get` для неизвестного id даёт `NotFound`.
   `count` возвращает число пользователей.
3. **`MemPosts`** хранит посты. `add` выдаёт id подряд, начиная с 1, общие на все авторы; автора
   не проверяет. `by_author` возвращает посты автора в порядке добавления.
4. **`SlowUsers` и `SlowPosts`** обёртки над любым портом (`Arc<dyn …>`): перед каждым вызовом ждут
   заданное время (`tokio::time::sleep`), потом передают вызов внутрь и возвращают его результат как есть.
   Они понадобятся тестам, чтобы видеть, ходят ли за данными вместе или по очереди.
5. **`Service`** держит `Arc<dyn UserRepo>` и `Arc<dyn PostRepo>`:
   - `register(name)` создаёт пользователя;
   - `publish(author, body)` сначала проверяет, что автор существует (`NotFound`, если нет, и тогда
     порт постов не трогается), потом добавляет пост;
   - `profile(id)` возвращает пользователя и его посты. Оба запроса идут одновременно, не по очереди;
     если пользователя нет, ответ `NotFound`.
6. **`Commands`** таблица команд `"сервис.метод"` с асинхронными обработчиками.
   - `register(name, handler)` принимает любую подходящую функцию или замыкание: `Fn(Vec<String>)`,
     возвращающее future с ответом `Response`. Повторная регистрация имени заменяет обработчик.
   - `dispatch(name, args)` вызывает обработчик; для неизвестного имени `Response::UnknownCommand`.
   - `Commands::new(service)` регистрирует три стандартные команды:
     `user.register <имя>` отвечает `Response::Ok(id)`;
     `post.publish <автор> <текст>` отвечает `Response::Ok(id поста)`;
     `user.profile <id>` отвечает `Response::Ok("имя:число_постов")`.
     Неверное число аргументов, нечисловой id и ошибки порта дают `Response::Error(..)` с любым текстом.
7. Все future методов `Service` и `Commands::dispatch` должны быть `Send`: таблицу вызывают из разных
   задач.

## Критерии приёмки

`cargo test --workspace` в корне проекта: все тесты `crates/memory/tests/acceptance.rs` проходят.
Они проверяют поведение хранилищ, отказ публикации от неизвестного автора, одновременные запросы
профиля (на замороженном времени: 50 мс вместо 100), стандартные команды, добавление своих обработчиков,
вызов из многих задач и `Send`-ность future на этапе компиляции. Решение должно проходить
`cargo clippy --workspace --all-targets -- -D warnings`.

## Что вспомнить из главы

Трейты за `dyn` (atr4), время жизни в `BoxFuture` (atr5), таблица обработчиков (atr6), одновременный
запрос через `join!` (прошлая глава), проверка `Send` (atr11).
