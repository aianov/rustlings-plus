# Замыкания

Булочная принимает заказы, и кассе нужно показать их в разном порядке: по сумме, по времени, по
имени клиента. Писать три функции сортировки глупо, поэтому у `sort_by_key` есть параметр «как достать
ключ», и в него отдают кусочек кода:

```rust
orders.sort_by_key(|o| o.total_cents);
let min_total = 500;
let big: Vec<_> = orders.iter().filter(|o| o.total_cents >= min_total).collect();
```

Второй `|o| ...` делает больше, чем кажется: он читает переменную `min_total` из окружающей функции.
Обычная функция так не умеет. Кусок кода вместе с пойманными переменными окружения и есть
**замыкание**. На них стоят итераторы, обработчики событий, потоки, шины сообщений, и до конца курса
мы будем писать их постоянно. Две анимации к главе открываются клавишей `v`: что именно замыкание
забирает из окружения и как вложены три трейта `FnOnce`, `FnMut`, `Fn`.

## Синтаксис и тип

```rust
let add = |a: i32, b: i32| -> i32 { a + b };
let double = |x| x * 2;          // типы выведены по первому использованию
let unit = || println!("tick");  // без параметров
```

Типы параметров и результата выводятся, но только один раз: `double(1_i32)` закрепит `i32`, и после
этого `double(1.5)` не соберётся. Главное, что надо усвоить: **у каждого замыкания свой, уникальный
тип**, который нельзя написать словами. Два замыкания с одинаковым телом это два разных типа. Поэтому

```rust
let k = 3;
let ops = [move |x: i32| x + k, move |x: i32| x * k];   // ошибка: expected closure, found a different closure
```

не соберётся. Замыкания без захвата компилятор ещё умеет привести к общему указателю на функцию (о нём
ниже), а с захватом нет. Поэтому в любом хранилище разнотипных замыканий (вектор, поле структуры, таблица) их
приходится прятать за трейт-объект: `Vec<Box<dyn Fn(i32) -> i32>>`. Если замыкание ничего не захватывает,
оно по размеру пустое; захватывает N значений, и это структура с N полями.

## Что замыкание захватывает

Компилятор смотрит на тело и берёт из окружения **минимум**, который нужен:

```rust
let name = String::from("pita");
let mut sold = 0;
let say = || println!("{name}");      // только читает name: берёт &name
let mut sell = || sold += 1;          // меняет sold: берёт &mut sold
let eat = || drop(name);              // отдаёт name дальше: забирает name целиком
```

Захват по `&` и `&mut` это обычные заимствования с обычными правилами: пока `sell` жив, к `sold`
никто другой не притронется. Это и есть причина ошибки «cannot borrow as immutable because it is also
borrowed as mutable», когда замыкание-счётчик хранят и одновременно читают его переменную. Решения
стандартные: сократить время жизни замыкания (оно живёт до последнего вызова, а не до конца
области), убрать замыкание вовсе или положить счётчик в `Cell`.

Начиная с edition 2021 замыкание захватывает **отдельные поля**, а не структуру целиком:

```rust
let mut shop = Shop { name: "Rye".into(), sales: 0 };
let mut sell = || shop.sales += 1;     // захвачено только shop.sales
println!("{}", shop.name);             // другое поле: можно
sell();
```

Это работает, пока замыкание обращается к полю напрямую. Вызов метода `shop.record()` захватит
`shop` целиком, и разделение пропадёт.

Ключевое слово `move` меняет **способ** захвата: все используемые переменные уезжают внутрь по
значению. `Copy`-типы при этом копируются, и снаружи остаётся независимая копия:

```rust
let mut n = 1;
let mut inc = move || { n += 1; n };
inc(); inc();
println!("{n}");    // 1: замыкание считало свою копию
```

## FnOnce, FnMut, Fn

Захват определяет, что замыкание умеет в **теле**, а от этого зависит, сколько раз его можно звать. Три
трейта вложены друг в друга:

```
  Fn      читает захваченное              можно звать много раз, даже через &
  FnMut   меняет захваченное              можно звать много раз, нужен &mut
  FnOnce  отдаёт захваченное              можно звать один раз
```

Любое `Fn`-замыкание годится и там, где просят `FnMut`, а любое `FnMut` там, где просят `FnOnce`.
Обратное неверно. Важно, что трейт определяется **телом**, а не словом `move`: `move || x + 1` по-прежнему
`Fn`, просто `x` лежит внутри. А замыкание, которое отдаёт захваченную строку, `FnOnce`, и второй вызов
не соберётся («use of moved value: f»).

Отсюда правило для сигнатур: **в параметре требуй самый слабый трейт, который тебе нужен**. Если
функция зовёт обработчик один раз, пиши `F: FnOnce()`: подойдёт любое замыкание. Если зовёт много раз
подряд, `FnMut`. Если зовёт через общую ссылку или из нескольких потоков, `Fn`. Требовать `Fn` «на
всякий случай» значит отказать тем, кто хотел передать счётчик. Из этого же следует, что вызвать
`FnMut` через `&F` нельзя: нужен `&mut F` или `mut f`. А вот `Option<F>` с `take()` это стандартный приём
для «выполнить один раз, даже если метод зовут повторно». Например, одноразовая ленивая загрузка:

```rust
struct Once<F: FnOnce() -> u32> { init: Option<F> }
impl<F: FnOnce() -> u32> Once<F> {
    fn call(&mut self) -> Option<u32> { self.init.take().map(|f| f()) }
}
```

Второй `call` вернёт `None`: замыкание уже забрали, звать нечего. Если нужна очередь разных одноразовых
действий, их кладут в `Vec<Box<dyn FnOnce()>>`: `Box<dyn FnOnce()>` можно вызвать, и вызов забирает ящик,
так что задачи вынимают из вектора и запускают по одной.

## move, клонирование и 'static

Когда замыкание должно пережить место, где его создали (поток, поле структуры, возвращённое
значение), оно не может ссылаться на локальные переменные. Тогда пишут `move` и приносят с собой
собственные копии. Если значение нужно нескольким замыканиям, перед `move` клонируют:

```rust
let tx = tx.clone();                       // ещё один отправитель
thread::spawn(move || tx.send(job_id));    // уехал в поток
```

Частая ошибка в цикле: `move` в теле цикла утаскивает общий `String` на первой же итерации, а на второй
компилятор говорит «value moved into closure here, in previous iteration of loop». Клонировать надо
внутри цикла, на каждой итерации свой экземпляр, либо вместо `String` делить `Rc<str>` / `Arc<str>`.

Требование `'static` читают не как «живёт вечно», а как «не содержит ссылок на чужие локальные
данные». Замыкание с `move`, владеющее только своими значениями, `'static`. Замыкание, держащее `&x`
на локальную `x`, нет.

## Указатели на функции

`fn(i32) -> i32` с маленькой буквы это не трейт, а тип: указатель на код, одно слово. Обычные
функции и замыкания **без захвата** к нему приводятся:

```rust
fn bread(n: u32) -> u32 { n * 3 }
let table: [(&str, fn(u32) -> u32); 2] = [("bread", bread), ("bun", |n| n * 2)];
```

Захватывающее замыкание в такую таблицу не положить: у него есть данные, а у указателя одно слово. Зато
указатель на функцию реализует все три `Fn`-трейта, так что его можно передать туда, где ждут
замыкание, и положить в `Box<dyn Fn>` рядом с захватывающими. Таблица `fn`-указателей не выделяет
память и годится для фиксированных наборов команд. Для настраиваемых нужен `Box<dyn Fn>`.

## Принимаем замыкание

```rust
fn twice(f: impl Fn(u32) -> u32, x: u32) -> u32 { f(f(x)) }      // статически, без Box
fn all(fs: &[&dyn Fn(u32) -> u32], x: u32) -> Vec<u32> { .. }    // разные замыкания в одном срезе
struct Timer { on_tick: Box<dyn FnMut()> }                       // долгоживущее поле
```

`impl Fn` и `<F: Fn>` создают отдельную копию функции под каждый тип замыкания: быстро (вызов
может встроиться), но все вызовы в одном месте имеют один тип. `&dyn Fn` один код на все типы и
косвенный вызов; подходит, когда типы смешаны, а замыкание нужно только на время вызова. `Box<dyn Fn>`
владеет замыканием и подходит для хранения. В поле структуры `Box<dyn Fn()>` без указания лишнего
означает `Box<dyn Fn() + 'static>`, и принять в `new` нужно `impl Fn() + 'static`, иначе компилятор не
сможет доказать, что замыкание не оборвётся.

## Возвращаем замыкание

```rust
fn adder(n: i32) -> impl Fn(i32) -> i32 { move |x| x + n }
fn pick(double: bool) -> Box<dyn Fn(i32) -> i32> {
    if double { Box::new(|x| x * 2) } else { Box::new(|x| x + 1) }
}
```

`impl Fn` значит «один конкретный тип, который я не называю». Без `move` замыкание сошлётся на параметр
`n`, который исчезнет при возврате («closure may outlive the current function»). Когда ветки возвращают
разные замыкания, тип уже не один, и нужен `Box<dyn Fn>`. Замыкание с состоянием возвращают как
`impl FnMut`, и вызывающий держит его в `let mut`.

## Запуск в потоках и получатель self: &Arc<Self>

Метод, который раздаёт работу потокам, не может отдать `&self` в `thread::spawn`: поток может пережить
вызов, а ссылка нет. Если владелец лежит в `Arc`, метод может принять сам умный указатель:

```rust
impl Pool {
    fn start(self: &Arc<Self>) -> Vec<thread::JoinHandle<u32>> {
        (0..self.workers.len()).map(|i| {
            let me = Arc::clone(self);
            thread::spawn(move || me.workers[i](i as u32))
        }).collect()
    }
}
```

Вызов выглядит как обычно, `pool.start()` при `pool: Arc<Pool>`. Поток получает свой клон `Arc` и номер
обработчика, `'static` выполнено. Собирай `JoinHandle` в вектор и жди после того, как запущены все:
`join` внутри того же цикла превратит параллельный запуск в последовательный.

## Обработчики в структурах

Реестр обработчиков обычно выглядит так:

```rust
type Handler = Box<dyn Fn(&Request) -> Response + Send + Sync + 'static>;
```

Каждая граница отвечает на отдельный вопрос. `Box<dyn ..>` потому что размеры разные. `Fn` потому что
реестр зовёт обработчики много раз и, возможно, одновременно. `Send` потому что реестр уйдёт в другой
поток. `Sync` потому что к нему будут обращаться из нескольких потоков по общей ссылке. `'static`
потому что обработчик переживёт функцию, которая его положила. Из границ вытекает, что внутри нельзя
держать `Rc` и `RefCell` (не `Send`/`Sync`) и ссылки на локальные данные. Вместо `Rc<RefCell<T>>` пишут
`Arc<Mutex<T>>`, вместо `Cell` атомики. Обрати внимание: `Cell<u32>` это `Send`, но не `Sync`, поэтому
замыкание с ним не `Sync`.

## Колбэки, пока меняется self

Объект хранит слушателей и сообщает им о себе:

```rust
fn notify(&mut self) {
    for listener in self.listeners.iter_mut() {
        listener(self);              // ошибка: self занят, итерация держит &mut self.listeners
    }
}
```

Слушателю нужен `&self`, а итератору нужен `&mut self.listeners`: конфликт. Тот же конфликт бывает и без
слушателей, у любого планировщика, который гоняет задачи и пишет результат в свой журнал:

```rust
struct Scheduler { jobs: Vec<Box<dyn FnMut() -> u32>>, log: Vec<u32> }
fn run(&mut self) {
    for job in self.jobs.iter_mut() {
        let r = job();
        self.record(r);              // ошибка: self.jobs занят обходом, а record берёт &mut self
    }
}
```

Стандартный выход: временно вынуть список методом `std::mem::take`, обойти, вернуть на место. Пока список
вынут, `self` свободен.

```rust
let mut jobs = std::mem::take(&mut self.jobs);
for job in jobs.iter_mut() { let r = job(); self.record(r); }
self.jobs = jobs;
```

Пока список вынут, `self.listeners` пуст, это надо иметь в виду, если слушатель может добавить
нового. Если ошибиться и не вернуть, объект «забудет» всех подписчиков после первого события.

## Типичные ошибки

Требовать `Fn` там, где хватит `FnMut` или `FnOnce`. Забыть `move` у замыкания для потока. Клонировать
`Arc` внутри `move`-замыкания вместо клонирования перед ним: `Arc` уже уехал в замыкание целиком, клонировать
его «снаружи» поздно, а если клон делать внутри, он заберёт тот же единственный экземпляр. Хранить замыкание-счётчик и читать его
переменную. Пытаться положить разнотипные замыкания в `Vec` без `Box`. Возвращать `impl Fn` из `if` с
двумя разными замыканиями. Класть `Rc` в обработчик, который должен быть `Send`.
