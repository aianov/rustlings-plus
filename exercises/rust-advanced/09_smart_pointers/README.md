# Умные указатели и владение ресурсами

Пул подключений к базе. Запрос берёт соединение, работает с ним и обязан вернуть в пул. Если вернуть вручную,
в какой-нибудь ветке с `return` или после паники об этом забудут, и через час пул опустеет. Умный указатель
берёт заботу на себя: он отдаёт соединение, а когда исчезает из области видимости, само соединение
возвращается в пул.

```rust
struct Lease<'a> { pool: &'a Pool, conn: Option<Conn> }

impl Deref for Lease<'_> { type Target = Conn; fn deref(&self) -> &Conn { self.conn.as_ref().unwrap() } }
impl Drop for Lease<'_> { fn drop(&mut self) { if let Some(c) = self.conn.take() { self.pool.put_back(c); } } }

let lease = pool.take();
lease.query("select 1");     // это Conn, хотя у нас Lease: вызов идёт через Deref
                             // здесь lease уничтожается, и соединение вернулось в пул
```

Здесь сразу три идеи этой главы: `Deref` (обёртка ведёт себя как внутреннее значение), `Drop` (код при
уничтожении) и RAII (ресурс привязан к времени жизни переменной). Дальше про указатели, которые делят владение
(`Rc`, `Arc`), про изменение через общую ссылку (`Cell`, `RefCell`), про слабые ссылки и про значения,
которые создаются лениво. `Box`, `Rc`, `Arc` и `Cow` в общих чертах уже знакомы, здесь их тонкости. Две
анимации (клавиша `v`) показывают счётчики `Rc` вместе с циклом и порядок уничтожения.

## Deref и deref coercion

`Box<T>` простейший владеющий указатель: значение лежит в куче, а `Box` в стеке держит адрес и освобождает память при уничтожении. Именно на `Box` проще всего смотреть, как работают `Deref` и `Drop`, поэтому дальше он будет в примерах.

`Deref` даёт писать `*wrapper` и вызывать методы внутреннего значения прямо на обёртке. Компилятор
сам разворачивает цепочку: если функции нужен `&str`, а у тебя `&Box<String>`, он применит `deref` дважды.

```rust
fn shout(s: &str) -> String { s.to_uppercase() }

let boxed: Box<String> = Box::new("hello".to_string());
shout(&boxed);        // &Box<String> -> &String -> &str, три типа, ни одного явного преобразования
```

Это работает только для ссылок и только в местах, где тип известен (аргумент функции, присваивание с типом).
Передать `boxed` по значению туда, где ждут `&str`, нельзя. `DerefMut` даёт то же для изменяемых ссылок.
Метод `deref(&self)` получает общую ссылку, поэтому если хочется считать обращения, счётчик придётся
держать в `Cell`.

`Deref` это про умные указатели, а не про наследование. Заводить `Deref` для типа, который «как бы
представляет» другой, плохая идея: методы внутреннего типа внезапно становятся методами обёртки, и читатель кода
перестаёт понимать, откуда что берётся.

## Drop и порядок уничтожения

`Drop::drop` вызывается автоматически, когда значение выходит из области видимости. Порядок строгий:

```
локальные переменные           в обратном порядке объявления
поля структуры                 в порядке объявления в структуре
элементы Vec, массива, кортежа по порядку, с нулевого
временные значения             в конце выражения (в конце оператора ;)
```

```rust
struct Stage { lights: Lights, sound: Sound }   // сначала умрёт lights, потом sound

let a = Lights::new();
let b = Sound::new();
// конец блока: сначала b, потом a (как стопка тарелок)
```

Раньше срока значение уничтожают через `drop(value)` (это обычная функция, она просто забирает значение
и ничего с ним не делает). Метод `value.drop()` вызвать нельзя, компилятор запретит. Из значения с `Drop`
нельзя перемещать поля по частям, иначе деструктор получил бы наполовину пустой объект. Есть и `mem::forget`: он
забывает значение без вызова `Drop`. Это не `unsafe`, но почти всегда ошибка, потому что ресурс утечёт.
Паника тоже вызывает деструкторы (раскрутка стека), поэтому охранники откатывают состояние и на пути ошибки.

## RAII-охранник и ловушка с подчёркиванием

RAII (ресурс получают при создании объекта и отдают при его уничтожении).
Так устроены `MutexGuard` (блокировка снимается сама), `File` (закрывается сам), транзакция БД (откат, если не
`commit`). Охранник должен жить ровно столько, сколько нужна защита. Главная ловушка в том, как его назвать:

```rust
let _ = lock_it();       // значение никуда не привязано, уничтожается СРАЗУ, защиты нет
let _guard = lock_it();  // привязано к _guard, живёт до конца блока
lock_it();               // оператор-выражение: тоже сразу, плюс предупреждение must_use
```

`_` не имя, это шаблон «не сохранять». Если охранник нужен ради побочного эффекта, дай ему
имя с подчёркиванием в начале (`_guard`): так компилятор не ругается на неиспользуемую переменную, а значение
остаётся жить.

## mem::take, replace, swap

Из `&mut T` нельзя просто забрать значение (`cannot move out of a mutable reference`): после этого там
осталась бы дырка. Но можно подставить на его место другое:

```rust
let old = std::mem::replace(&mut self.name, new_name);   // старое вернули, новое на месте
let all = std::mem::take(&mut self.buffer);              // забрали, оставили Default (пустой Vec)
std::mem::swap(&mut self.front, &mut self.back);         // обменяли два места
let first = self.cursor.take();                          // то же для Option: забрал Some, оставил None
```

Для переходов состояния enum по `&mut self` это основной приём: временно подставляем любой вариант, забираем
старое значение через `replace`, разбираем его по частям и записываем итоговое состояние:

```rust
match std::mem::replace(self, State::Poisoned) {
    State::Running(job) => *self = State::Done(job.finish()),
    other => *self = other,
}
```

## Cell и RefCell: изменение через общую ссылку

Иногда изменять нужно, а изменяемой ссылки нет: значение раздали по `&` в несколько мест, или метод вынужден
брать `&self` (как `Deref::deref`). Внутренняя изменяемость переносит проверку правил заимствования с этапа
сборки на этап выполнения.

`Cell<T>` для маленьких значений: `get` и `set` копируют значение внутрь и наружу (для `T: Copy`), а `replace`
работает с любыми типами, `take` только с теми, у кого есть `Default` (оставляет на месте значение по умолчанию). Ссылку на содержимое `Cell` не отдаёт, поэтому ничего не ломается.

`RefCell<T>` для всего остального: `borrow()` даёт `Ref<T>` (общая ссылка), `borrow_mut()` даёт `RefMut<T>`.
У `RefCell` тоже есть `take` и `replace`: они забирают содержимое целиком и оставляют на месте новое (`take` ставит `Default`).
Правило прежнее: либо много читателей, либо один писатель. Нарушение это паника `already borrowed`, а не ошибка
сборки. `try_borrow` и `try_borrow_mut` возвращают `Result`, если паника не нужна.

```rust
let log = RefCell::new(Vec::<String>::new());
log.borrow_mut().push("start".into());       // заём живёт до конца оператора
let n = log.borrow().len();                   // и здесь тоже, поэтому два оператора не конфликтуют
```

Заём живёт, пока жив `Ref` или `RefMut`. Ловушки:

```rust
match cache.borrow().get(&key) {              // временное значение borrow() живёт ВЕСЬ match
    Some(v) => cache.borrow_mut().insert(..), // паника: чтение ещё не закончилось
    None => ..
}
```

Берегись и рекурсии: функция держит `borrow_mut()` и вызывает саму себя. Правило: заём короткий, не держи его
через вызовы чужого кода и рекурсию. Сначала достань нужное (`.copied()`, `.cloned()`), заём кончился,
потом делай остальное.

## Rc<RefCell<T>>: общее изменяемое

`Rc<T>` даёт много владельцев одного значения, но только для чтения. `Rc<RefCell<T>>` даёт много владельцев
изменяемого значения: типичный способ связать части программы, у которых нет единого владельца (подписчики,
узлы графа). Главное, что нужно помнить: `Rc::clone(&x)` копирует только указатель и увеличивает счётчик,
а не данные. Запись `x.borrow().clone()` клонирует содержимое, получается другая независимая копия.
Сравнивать «тот ли это объект» нужно через `Rc::ptr_eq` (у `Arc` есть такой же `Arc::ptr_eq`), а не по содержимому: два пустых ящика равны по
содержимому, но это разные ящики.

## Weak и циклы

Каждая `Rc` увеличивает счётчик сильных ссылок, значение уничтожается, когда счётчик доходит до нуля. Если два
значения держат друг друга через `Rc`, счётчики не обнулятся никогда: утечка. Компилятор тут не поможет, это
не небезопасно в смысле Rust, но память не вернётся и `Drop` не вызовется.

```
родитель ──Rc──▶ ребёнок
   ▲                │
   └────Rc──────────┘     цикл: у каждого счётчик не меньше 1, освободить некому
```

Правило: ссылки «по владению» вниз сильные, «знание о другом» вверх слабые. `Weak<T>` не держит значение
живым. `Rc::downgrade(&rc)` создаёт `Weak`, `weak.upgrade()` возвращает `Option<Rc<T>>`: `Some`, пока значение живо,
иначе `None`. Если `upgrade` вернул `Some`, у тебя снова есть сильная ссылка, и значение будет жить, пока ты её держишь.
`Rc::strong_count` и `Rc::weak_count` помогают проверять себя.

## Arc, Arc<str> и копирование при записи

`Arc` то же, что `Rc`, но счётчик атомарный, поэтому `Arc<T>` можно отдавать потокам (если `T: Send + Sync`).
Атомарные операции дороже обычных, поэтому в однопоточном коде бери `Rc`.

Неизменяемые данные, которые раздают многим, выгодно хранить как `Arc<str>` вместо `String` и `Arc<[T]>`
вместо `Vec<T>`: клон это один атомарный счётчик, лишнего поля ёмкости нет, а читать можно как обычный `&str`
или `&[T]`. Создать их можно из `String` и `Vec` через `Arc::from` или `.into()`.

Когда общие данные иногда нужно менять, пригодится копирование при записи:

```rust
let mut cfg: Arc<Config> = ..;
Arc::make_mut(&mut cfg).retries = 5;     // если cfg единственный владелец, правит на месте;
                                         // если есть другие, клонирует Config и правит свою копию
```

`Arc::try_unwrap(arc)` достаёт значение, если владелец один, иначе возвращает `Err(arc)` обратно. Для `Rc`
всё то же (`Rc::make_mut`, `Rc::try_unwrap`).

## OnceLock, LazyLock, OnceCell

Глобальное значение, которое нельзя вычислить при сборке (чтение файла, `HashMap` с данными), кладут в
статик не напрямую, а в ленивую обёртку:

```rust
static ROUTES: LazyLock<HashMap<&'static str, u16>> = LazyLock::new(|| HashMap::from([("home", 1), ("feed", 2)]));
static CONFIG: OnceLock<Config> = OnceLock::new();     // потом: CONFIG.get_or_init(load_config)
```

`LazyLock` создаётся при первом обращении, замыкание задано сразу. `OnceLock` можно инициализировать снаружи
позже и ровно один раз, даже при гонке потоков. `OnceCell` то же самое для однопоточного случая, подходит
для поля структуры (кэш тяжёлого результата). Все три гарантируют: инициализация выполнится один раз, остальные
вызовы увидят готовое значение.

`static mut` для счётчиков и справочников не нужен. Любое обращение к нему `unsafe`, и ответственность за отсутствие
гонок на тебе. Для числа берут `AtomicU32` и подобные, для набора данных `LazyLock` (или `Mutex` внутри, если нужна запись).

## Типичные ошибки

Писать `let _ = guard();` и удивляться, что защиты нет. Держать `borrow_mut()` через рекурсию или вызов чужого кода.
Заводить `Rc` в обе стороны и получать утечку. Клонировать содержимое (`.borrow().clone()`) там, где хотели делиться.
Сравнивать `Rc` по содержимому вместо `ptr_eq`. Использовать `Deref` ради «наследования». Брать `Arc`
там, где хватает `Rc`, и платить за атомарность. Забирать значение из `&mut` через `clone` и `clear`, когда есть `mem::take`.
Оставлять `static mut` в многопоточном коде.
