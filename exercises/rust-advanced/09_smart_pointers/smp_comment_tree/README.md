# Проект: дерево комментариев

В соцсети под постом идёт обсуждение: комментарии, ответы на комментарии, ответы на ответы. Нужно хранить
их деревом так, чтобы удаление ветки сразу освобождало память, ссылки «вверх» не создавали утечек, а правки
были видны всем, кто держит комментарий. Библиотека `comment-tree` собирает это из умных указателей.

## Что нужно сделать

В `src/lib.rs` объявлены типы и сигнатуры, тела пустые.

1. `Thread::post(author, text)` создаёт корневой комментарий и отдаёт на него `Rc`. Тред владеет корнями.
2. `Comment::reply(&Rc<Comment>, author, text)` создаёт ответ. Родитель владеет детьми (`Rc` вниз), ребёнок
   знает родителя слабо (`Weak` вверх): иначе получится цикл, и ветка никогда не освободится.
3. `parent`, `children`, `author`, `path` (авторы от корня через `/`), `depth`, `size` (число комментариев в
   ветви, включая себя), `Thread::roots`, `Thread::total`.
4. `text` и `edit`: комментарий меняется по общей ссылке (`RefCell`), правка видна через любой `Rc` на него.
5. `Thread::remove(&Rc<Comment>)` отцепляет комментарий (из корней или из детей родителя) и возвращает
   `true`, если он там был. Отцепленная ветвь забывает родителя. Если снаружи на неё никто не ссылается, она
   освобождается сразу.
6. Счётчик живых комментариев: `Live` это охранник (RAII), он увеличивает общий счётчик при создании и
   уменьшает в `Drop`. Каждый комментарий хранит один `Live`. `Thread::live()` показывает, сколько комментариев
   сейчас живо (ответ `Comment::reply` берёт счётчик у родителя, а не заводит свой), `Thread::live_counter()` отдаёт сам счётчик (проверка утечек после уничтожения треда).
7. `Comment::tags()`: слова вида `#слово` (после `#` идут буквы и цифры), которые есть в словаре
   (`rust` даёт `programming`, `cats` даёт `pets`, `food` даёт `life`), без повторов, в порядке появления, регистр
   не важен. Словарь строится лениво, один раз за всё время работы программы (`LazyLock`), на счётчик
   `dictionary_builds` смотри в тестах.

## Как проверить

```
cargo test
cargo clippy --all-targets -- -D warnings
```

## Подсказки по теории

Сильные ссылки идут по владению (родитель к детям), слабые против него (ребёнок к родителю). `Rc::downgrade`
делает слабую ссылку, `upgrade` возвращает `Option`. Сравнивать комментарии как «тот же самый» нужно через
`Rc::ptr_eq`, а не по содержимому. Не держи `borrow()` или `borrow_mut()` дольше, чем нужно: при рекурсии
по дереву или при удалении можно получить панику «already borrowed».
