# Производительность без профилировщика

Интернет-магазин строит страницу каталога, и на сотне товаров всё летает. Во время распродажи товаров стало
сто тысяч, и страница открывается полминуты. Разработчик начинает «оптимизировать» то, что кажется
медленным: меняет цикл на итератор, вставляет `#[inline]`, переписывает форматирование. Ничего не помогает,
потому что узкое место было в другом: поиск по списку внутри цикла и копия каждого товара вместо ссылки.
Оптимизация вслепую не работает. Сначала измерь, потом поменяй одну вещь, потом измерь снова.

Эта глава о том, как понять без внешних инструментов, куда уходят время и память, и об очевидных ловушках:
лишние копии, повторные выделения, квадратичные алгоритмы, нечестные замеры. Профилировщики, нагрузочное
тестирование и узкие места живого сервиса разбираются позже, в разделе services. Здесь всё на `std`.

## Стек, куча и сколько что весит

Значение типа лежит либо на стеке (размер известен заранее, освобождается само), либо в куче (запрашивается у
аллокатора, стоит дороже). `Vec`, `String`, `Box` держат на стеке маленький заголовок, а данные в куче:

```
 стек                      куча
 Vec<u32>: ptr ───────────► [ 7 | 3 | 9 | _ | _ | _ | _ | _ ]
           len = 3           ^^^^^^^^^^^   занято ёмкостью
           cap = 8                         (все 8 мест выделены)
```

Заголовок `Vec` и `String` это три слова (24 байта на 64-битной машине), `Box<T>` и `&T` одно слово, `&[T]` и
`Box<[T]>` два (указатель и длина). Размер любого типа даёт `std::mem::size_of::<T>()`, а размер значения за
срезом `std::mem::size_of_val`. Память вектора определяет **ёмкость**, а не длина: `Vec::with_capacity(1000)`
занимает место под тысячу, даже когда пуст.

### Ниши: когда `Option` ничего не стоит

Если у типа есть значение, которого не бывает, `None` помещается туда, и лишняя метка не нужна. Ссылки и
`Box` не бывают нулевыми, `NonZeroU32` не бывает нулём, `char` не бывает выше `0x10FFFF`, `Vec` хранит
ненулевой указатель. Поэтому:

```rust
use std::mem::size_of;
assert_eq!(size_of::<Option<&String>>(), size_of::<&String>());       // 8 и 8
assert_eq!(size_of::<Option<Vec<u8>>>(), size_of::<Vec<u8>>());       // 24 и 24
assert!(size_of::<Option<u64>>() > size_of::<u64>());                 // 16 против 8: свободных значений нет
```

### Большой вариант enum

Размер enum равен размеру самого большого варианта плюс метка. Так один редкий тяжёлый вариант раздувает
все значения:

```rust
enum Shape {
    Dot,                      // 0 полезных байт
    Circle(f32),              // 4
    Poly([f32; 64]),          // 256
}
// size_of::<Shape>() около 260: вектор из миллиона точек весит как миллион многоугольников
```

Лекарство в том, чтобы вынести тяжёлое в кучу (`Poly(Box<[f32; 64]>)`): вариант занимает 8 байт, а за
многоугольник платит только тот, у кого он есть. Проверяй `size_of`, а не на глаз: тест вроде
`assert!(size_of::<Shape>() <= 16)` ловит возврат проблемы.

## Копии, которых можно избежать

Аллокатор вызывают при `String::from`, `to_string`, `format!`, `clone` вектора и строки, `to_lowercase`,
`collect` в новый вектор. Каждый такой вызов оправдан, только если без него нельзя. Четыре способа обойтись:

- **Заимствовать.** Функция, которой нужно прочитать, принимает `&str` и `&[T]`, а не `String` и `Vec<T>`. Результат,
  который является частью входа, возвращай срезом: `Vec<&str>` вместо `Vec<String>`.
- **Cow.** Когда копия нужна только иногда, возвращай `Cow<'_, str>`: `Cow::Borrowed(s)`, если строка не
  изменилась, и `Cow::Owned(новая)`, если изменилась. Так «обрезать пробелы или ничего не делать» не платит
  за нормальные строки.
- **Arc.** Когда одно значение нужно многим владельцам, клонируй `Arc<T>`: это увеличение счётчика, а не копия
  данных. Тысяча записей в логе ссылается на один профиль.
- **Переиспользовать буфер.** Не создавай новый `Vec` или `String` в цикле. Заведи один снаружи, а внутри делай
  `buf.clear()`: он обнуляет длину, но сохраняет ёмкость.

```rust
use std::fmt::Write;

// плохо: на каждую ячейку format!, на строку Vec<String> и join
// хорошо: одна строка с запасом, запись прямо в неё
fn csv_row(cells: &[f64]) -> String {
    let mut out = String::with_capacity(cells.len() * 8);
    for (i, cell) in cells.iter().enumerate() {
        if i > 0 {
            out.push(',');
        }
        let _ = write!(out, "{cell:.2}");
    }
    out
}
```

Вектор растёт удвоением: первое `push` выделяет место на 4 элемента (для маленьких типов), пятое переносит на 8,
девятое на 16 и так далее, и каждый перенос это новое выделение плюс копирование. Если размер известен
заранее, `Vec::with_capacity(n)` или `reserve(n)` убирают все переносы. Если ты собираешь итератором с точной
длиной, `collect` сам выделит один раз. Посмотри анимацию `alloc_growth`.

## Квадратичные ловушки

На ста элементах всё равно, на ста тысячах решает вид кривой.

- `Vec::remove(0)` и `insert(0, x)` двигают весь вектор. Очередь на нём: каждое извлечение стоит `O(n)`,
  вся работа `O(n²)`. Нужен `VecDeque`: кольцевой буфер, у которого обе стороны дёшевы.
- `vec.contains(&x)` проходит по списку. В цикле по тому же размеру это `O(n²)`. Нужен `HashSet` (или
  `BTreeSet`, если важен порядок).
- Склеивание строк `s = s + &x` в цикле копирует всё накопленное каждый раз. Пиши `s.push_str(&x)` или
  `write!` в одну строку.
- Сортировка вставкой «найти место и вставить» в вектор это тоже `O(n²)`. Либо `sort`, либо, если нужны только
  первые `k` из `n`, `select_nth_unstable_by` и сортировка этих `k`.

## Честный замер

Время работы считают не на глаз и не одним запуском. Правила такие.

**Часы.** `std::time::Instant`: он монотонный, то есть не идёт назад. `SystemTime` можно подвинуть
синхронизацией часов, для замеров он не годится.

**Прогрев.** Первые запуски медленнее: холодные кэши, страницы памяти ещё не выделены. Их делают и
выбрасывают.

**Много запусков и статистика.** Один запуск врёт. Делают десятки и смотрят: минимум (лучший случай),
медиана (типичный), p99 (хвост, который видят самые невезучие запросы) и максимум. Среднее арифметическое не
используют: один выброс по 100 мс среди десяти замеров по 10 мс поднимает «среднее» вдвое. Анимация
`bench_noise` показывает, как разбросаны замеры одной и той же функции.

```rust
use std::time::{Duration, Instant};

fn median_of(runs: usize, mut f: impl FnMut()) -> Duration {
    let mut times: Vec<Duration> = (0..runs).map(|_| { let t = Instant::now(); f(); t.elapsed() }).collect();
    times.sort();
    times[times.len() / 2]
}
```

**Релиз.** `cargo run` и `cargo test` по умолчанию собирают без оптимизаций. Цифры оттуда годятся для
сравнения «до и после» на одной машине, но не для выводов о настоящей скорости. Для них нужен `--release`.

**black_box.** В релизе оптимизатор убирает вычисления, результат которых никому не нужен. Если замер
показывает «0 нс» или невероятно быстрый результат, скорее всего работу просто выбросили. Лекарство в
`std::hint::black_box`: он передаёт значение дальше так, что компилятор не может предсказать, что с ним
будет. Скрывай и вход, и выход: `black_box(f(black_box(&data)))`. Иначе вычисление можно вынести за цикл или
посчитать заранее.

## Свой счётчик аллокаций

Узнать, сколько раз код просит память, можно, подменив аллокатор. `GlobalAlloc` это трейт с четырьмя методами,
а `#[global_allocator]` регистрирует реализацию на всю программу. Обёртка над системным аллокатором,
которая считает вызовы:

```rust
use std::alloc::{GlobalAlloc, Layout, System};
use std::sync::atomic::{AtomicUsize, Ordering};

static CALLS: AtomicUsize = AtomicUsize::new(0);

struct Tally;

unsafe impl GlobalAlloc for Tally {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        CALLS.fetch_add(1, Ordering::Relaxed);
        unsafe { System.alloc(layout) }
    }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        unsafe { System.dealloc(ptr, layout) }
    }
}

#[global_allocator]
static ALLOCATOR: Tally = Tally;
```

Три правила. Внутри аллокатора нельзя ничего, что само выделяет память (`println!`, `format!`, `Vec`):
это рекурсия. Не забудь `alloc_zeroed` (через него идёт `vec![0; n]`) и `realloc` (рост вектора). И главное:
`cargo test` запускает тесты параллельно, а глобальные счётчики общие на весь процесс. Аллокации соседнего
теста попадут в твой замер, и проверка «здесь ноль аллокаций» будет флакать. Поэтому в тестах счётчик делают
**на поток**: `thread_local!` с `Cell<usize>`. Внутри аллокатора начальное значение задают константой
(`const { Cell::new(0) }`), чтобы локальное хранилище само не просило память, и читают через `try_with`:
при завершении потока хранилище уже может быть уничтожено.

Тест на число аллокаций устойчивее таймера: он не зависит от скорости машины. Фраза «лента из двадцати
карточек делает не больше ста аллокаций» либо верна, либо нет, на любом компьютере.

## Свой хеш и HashDoS

`HashMap` по умолчанию хеширует `SipHash`: он стойкий, то есть противник не может заранее подобрать ключи с
одинаковым хешем. Эта стойкость стоит времени. Для ключей, которые выдаёт сам сервис (номера, короткие
идентификаторы), годится простой хеш вроде FNV-1a, и карта становится быстрее и даже детерминированной по
порядку обхода. Подключается он через два трейта: `Hasher` (накопить байты, выдать число) и `BuildHasher`
(фабрика хешеров), а карта создаётся как `HashMap::with_hasher(...)`.

Для ключей из сети простой хеш опасен. Противник присылает набор ключей с совпадающим хешем, карта
вырождается в связный список, каждая вставка становится линейной, весь набор квадратичным, и сервис занят
одним запросом. Это называется HashDoS. Правило простое: хеш быстрого вида только для данных, к которым
у внешнего мира нет доступа.

## Таймер фаз на Drop

Когда непонятно, какая стадия обработки съедает время, на каждую ставят таймер: объект, который при
создании запоминает `Instant::now()`, а в `Drop` записывает прошедшее время в журнал. Главное достоинство
в том, что запись происходит при любом выходе из области: и при раннем `return`, и при `?`, и при панике.

```rust
let _timer = PhaseTimer::start(&recorder, "parse");   // живёт до конца блока
let _ = PhaseTimer::start(&recorder, "oops");         // ловушка: значение уничтожено сразу, фаза нулевая
```

Имя переменной с подчёркиванием (`_timer`) держит значение до конца области. Подчёркивание без имени (`_`)
не создаёт переменной, и `Drop` срабатывает мгновенно. Вложенные таймеры заканчиваются в порядке, обратном
созданию.

## Типичные ошибки

- Оптимизировать без замера или менять сразу много вещей: не поймёшь, что помогло.
- Верить одному запуску, среднему вместо медианы, цифрам из отладочной сборки.
- Замер без `black_box` в релизе.
- Глобальный счётчик в параллельных тестах.
- `to_string()` и `clone()` «на всякий случай» на горячем пути.
- `Vec::new()` и `format!` в цикле там, где можно переиспользовать буфер.
- `remove(0)` и `contains` в цикле на больших данных.
- Быстрый хеш для ключей от пользователей.
