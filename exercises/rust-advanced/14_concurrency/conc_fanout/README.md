# Проект: фоновая рассылка уведомлений

В сети появилось «подружиться»: когда один пользователь публикует пост, его друзья получают уведомление.
Автору нельзя ждать, пока уведомления уйдут (у популярного автора это сотни отправок), поэтому рассылка
идёт в фоне, в пуле потоков. Заодно сервис регистрирует пользователей, держит кэш профилей и считает,
сколько всего сделано. Всё на `std`, потоки общие, и каждая гонка здесь настоящая.

## Что уже есть

`crates/fanout/src/pool.rs` готовый маленький пул (`Pool::new`, `execute`, `close`, `is_closed`,
`wait_idle`, `Drop` ждёт рабочих). Менять его не нужно. Остальное пишешь ты в `src/lib.rs`: типы и сигнатуры
объявлены, тела пустые, поля структуры добавь сам.

## Что нужно сделать

1. `Fanout::new(workers, store, sink)`: сервис с пулом на `workers` потоков. `ProfileStore::load` это
   медленная загрузка имени профиля, `Sink::deliver` это отправка уведомления одному получателю.
2. `register(login)`: id начинаются с 1 и растут на единицу. Логин непустой, не длиннее 20 символов, только
   ASCII-буквы, цифры и `_` (иначе `Invalid`). Занятый логин это `Taken`. Если несколько потоков одновременно
   регистрируют один логин, успех у одного, а id не сгорают: следующий новый логин получает следующий номер.
3. `profile(id)`: имя из `store.load`, закэшированное на `RwLock`. Повторные запросы не ходят в хранилище.
   Все потоки, спросившие один профиль, получают один и тот же `Arc<String>`. Неизвестный id это `None`.
   Медленное `store.load` не держит замок, и профили разных пользователей загружаются одновременно.
4. `befriend(a, b)`: дружба взаимная, у каждого пользователя свой список друзей под своим замком.
   Операция идемпотентна. `a == b` это `FollowError::SameUser`, неизвестный id это `UnknownUser(id)`.
   Одновременные `befriend(x, y)` и `befriend(y, x)` не должны блокироваться навсегда. `friends(id)`
   возвращает друзей по возрастанию (для неизвестного id пусто).
5. `publish(author, text)`: ставит по одному заданию в пул на каждого друга и сразу возвращает число
   поставленных. Уведомление: `"<логин автора> опубликовал: <текст>"`. Неизвестный автор это `UnknownUser`,
   после `shutdown` это `Closed` (и ничего не считается).
6. `stats()`: `posts` (опубликовано), `queued` (поставлено уведомлений), `delivered`, `failed` (ошибка
   `Sink::deliver`). Счётчики атомарные, без общего замка.
7. `shutdown()`: больше не принимать публикации, дождаться, пока все поставленные уведомления
   отправлены, вернуть итоговые `Stats`. Можно вызывать несколько раз.

## Как проверить

```
cargo test --workspace
```

Приёмочные тесты лежат в `crates/fanout/tests/acceptance.rs`, их менять нельзя. Ожидания идут с таймаутами,
так что взаимная блокировка покажет ошибку, а не повиснет.
