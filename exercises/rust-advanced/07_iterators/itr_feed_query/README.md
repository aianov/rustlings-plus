# Проект: ленивая выборка ленты

Лента соцсети живёт в памяти, постов в ней десятки тысяч, а экран показывает три. Скрытых авторов и
удалённые посты надо отсеять, страницы отдать по номеру, и всё это без того, чтобы каждый запрос строил
вектор размером с ленту. Библиотека `feed-query` делает выборку цепочкой адаптеров, а собирает только
то, что действительно нужно вызывающему.

## Что нужно сделать

В `src/lib.rs` объявлены типы и сигнатуры, тела пустые.

1. `Feed::new(posts)` хранит посты по возрастанию `created` (вход может прийти в любом порядке;
   порядок равных меток сохраняется).
2. `Feed::visible(&hidden)` возвращает ленивый итератор по постам от новых к старым, без удалённых и без
   авторов из `hidden`. Он не строит никаких коллекций: первый пост находится без единой аллокации.
3. `Feed::since(&hidden, after)` то же, но только посты с `created > after`. Раз посты отсортированы, как
   только встретился пост не новее метки, дальше читать не нужно.
4. `Feed::authors(&hidden)` возвращает ленивый итератор по именам авторов видимых постов, каждое имя
   один раз, в порядке самых новых постов.
5. Свой адаптер: трейт `PagesExt` с методом `.pages(size)` у любого итератора, структура `Pages<I>` с
   `Item = Vec<I::Item>`. Последняя страница может быть неполной, пустой страницы не бывает. Адаптер
   ленивый (бесконечный источник читается ровно по странице). Размер ноль это паника
   `page size must be positive` при вызове `pages`.
6. `Feed::paged(&hidden, size)` страницы видимой ленты, `Feed::page(&hidden, number, size)` одна страница
   по номеру с нуля (`None`, если страницы нет). Страница собирается из ленивой цепочки: на страницу из трёх
   постов в ленте на пятьдесят тысяч допускается не больше двух аллокаций.

## Как проверить

```
cargo test
cargo clippy --all-targets -- -D warnings
```

В приёмочных тестах подсчитываются аллокации, поэтому `collect` посреди цепочки покажет себя сразу.

## Подсказки по теории

Тип результата `impl Iterator<Item = &Post> + '_` или с явным временем жизни говорит, что итератор
заимствует ленту и список скрытых авторов. Для нужного порядка пригодится `rev` на срезе (он быстрый:
срез знает свой конец). Страница по номеру это `skip(номер * размер)` и `take(размер)`: пропущенные посты не копируются
в память. Номер может быть огромным, умножение не должно паниковать. В адаптере страницу берут из
`by_ref().take(n)`: без `by_ref` итератор уехал бы в `take` целиком.
