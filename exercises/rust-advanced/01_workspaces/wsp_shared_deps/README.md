# Общие версии, поля и правила

В воркспейсе три крейта: `model`, `store` и программа `dump`. Они собираются, но живут каждый по себе:
версии пакетов 0.2.0, 0.3.1 и 0.1.0, часть крейтов на edition 2021, serde записан тремя разными способами,
правил проверок нет вообще. Любое обновление зависимости превращается в охоту по манифестам, а
забытый крейт отстаёт молча.

## Что должно получиться

1. Всё, что должно совпадать у крейтов, записано в корневом манифесте один раз, а в членах только
   ссылается на него:
   - версия пакета 0.5.0, edition 2024, лицензия MIT и rust-version 1.88 у всех трёх;
   - зависимости `serde` (с derive), `serde_json` и внутренние `model` и `store`;
   - правило компилятора `unsafe_code = "forbid"` действует в каждом из трёх крейтов.
2. Программа `dump` печатает JSON с ключами в порядке вставки: `{"zone":"eu","id":7,"name":"nightly"}`.
   Для этого serde_json собирается с feature `preserve_order`, но только для `dump`: остальные крейты
   и общая запись корня остаются как есть.
3. В Cargo.lock одна версия serde.

## Приёмка

```
cargo test --manifest-path acceptance/Cargo.toml
cargo run -p dump
```

Тесты читают манифесты (каждая зависимость члена обязана ссылаться на корень), спрашивают у cargo
метаданные пакетов и проверяют, что `unsafe` в любом из трёх крейтов ломает сборку.
