# Потерянный член воркспейса

В реестре бухгалтерии четыре крейта: `ledger-core`, `ledger-api`, `audit` и утилита `importer`.
Зелёный `cargo test --workspace` всех устраивает, пока кто-то не зайдёт в папку `audit` и не получит
ошибку про воркспейс. А ещё после работы в `tools/importer` в репозитории появляются второй
`Cargo.lock` и второй `target`.

## Что должно получиться

1. Все четыре крейта состоят в одном воркспейсе, и `cargo test --workspace` запускает тесты `audit`.
2. Из любой папки крейта `cargo build` работает и не заводит ни своего `Cargo.lock`, ни своего `target`.
3. Новые крейты в `crates/` и `tools/` попадают в воркспейс сами.
4. `cargo run -p importer -- 4 5 -1` печатает `imported 3 rows, total 8`.

## Приёмка

```
cargo test --manifest-path acceptance/Cargo.toml
```

Тесты копируют проект, собирают его, заходят внутрь каждого крейта и считают файлы `Cargo.lock` и
папки `target`.
