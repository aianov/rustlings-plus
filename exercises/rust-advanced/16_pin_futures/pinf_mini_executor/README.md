# Проект: мини-исполнитель

В соцсети на каждое входящее соединение пока заводится свой поток, и при тысяче подключений процесс
тонет в потоках. Нужен исполнитель: один поток, много задач, и каждая задача уступает, пока ждёт. Ты
пишешь такой исполнитель на `std`, без внешних крейтов. На нём потом держится понимание рантайма tokio.
Здесь всё в одном потоке: задачи не обязаны быть `Send`.

## Что нужно сделать

В `crates/mini-exec/src/lib.rs` объявлены типы и сигнатуры, тела пустые. Поля структур добавь сам.

1. `block_on(fut)`: довести future до конца в текущем потоке и вернуть результат. Пока future ждёт, поток
   спит (не крутит цикл), а пробуждение может прийти из любого потока.
2. `Executor::new()` и клон `Executor` (клоны делят одну очередь задач). `spawn(fut)` ставит задачу и
   возвращает `JoinHandle<T>`. `fut` может не быть `Send`, но обязан быть `'static`.
3. `JoinHandle<T>` это `Future<Output = T>`: готов, когда задача завершилась. Если задачу не ждут (хэндл
   выброшен), она всё равно выполняется до конца.
4. `Executor::run()` опрашивает задачи, пока не завершатся все. Если задач нет, возвращается сразу.
   `Executor::run_until(fut)` ведёт главный future (он может заимствовать локальные данные, `'static` не нужен)
   и все остальные задачи, и возвращается, когда готов главный; недоделанные задачи остаются в исполнителе.
   `pending_tasks()` отдаёт число незавершённых задач.
5. Порядок и количество опросов: свежая задача опрашивается в порядке `spawn`; задача, получившая `Pending`,
   встаёт в хвост очереди после своего пробуждения; несколько `wake` подряд до очередного опроса дают
   один опрос; без пробуждения задача не опрашивается вообще (ни по таймеру, ни вхолостую).
   Пока очередь пуста, исполнитель спит и просыпается от `wake` из любого потока.
6. `sleep(d)`: future, готовый через `d`, отсчёт от создания. Ждёт отдельный поток, а не исполнитель.
   Несколько `sleep` ждут одновременно. `yield_now()`: уступает очередь один раз и возвращается.

## Как проверить

```
cargo test --workspace
```

Приёмочные тесты лежат в `crates/mini-exec/tests/acceptance.rs`, их менять нельзя. Ожидания в них идут с
таймаутами, так что зависание покажет ошибку.

## Подсказки по теории

README главы и задачи `pinf14` (block_on), `pinf7` (таймер), `pinf16` и `pinf17` (очередь и пробуждения).
Очередь удобно держать как `Mutex<VecDeque<номер задачи>>` с `Condvar`: `Waker` кладёт номер и стучит.
Сами future хранятся в `Executor` в таблице «номер → задача», а в `Waker` лежит только номер: так задачам
не нужно быть `Send`.
