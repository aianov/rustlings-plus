# Байты и строки

Приложение для умных весов получает от устройства пакеты: название комнаты («Спальня 🛏️»), вес и
контрольная сумма. Пока в названиях была латиница, всё работало. Потом клиент из Киева назвал весы «Ванна»,
обрезка названия до 8 символов уронила сервис паникой, а пакет, пришедший по Bluetooth двумя кусками,
превратил «Ванна» в «Ван��». Ничего экзотического тут нет: это обычные байты, с которыми обошлись как с
обычными символами.

Эта глава о том, что лежит под `String` и сетевым протоколом: как устроен UTF-8, где в строке можно резать,
как читать числа из байт и как отличить «данных пока мало» от «данные испорчены». Это фундамент для своих
HTTP, WebSocket и protobuf дальше по курсу: там те же приёмы, только поверх протоколов.

## Строка это байты, которые обязаны быть UTF-8

В Rust `String` и `&str` хранят байты в кодировке UTF-8, и это гарантируется типом: невалидный UTF-8 в `str`
попасть не может. Один символ (скалярное значение Unicode, тип `char`) занимает от одного до четырёх байт:

```
символ     байты (hex)         сколько
a          61                   1
й          D0 B9                2
€          E2 82 AC             3
😀         F0 9F 98 80          4

первый байт говорит, сколько всего байт в символе:
  0xxxxxxx                              один байт (ASCII)
  110xxxxx 10xxxxxx                     два
  1110xxxx 10xxxxxx 10xxxxxx            три
  11110xxx 10xxxxxx 10xxxxxx 10xxxxxx   четыре
остальные («продолжения») всегда начинаются с битов 10
```

Отсюда три разные «длины» строки. `s.len()` это байты. `s.chars().count()` это символы (скалярные значения;
считается обходом, не за O(1)). То, что человек видит как «одну букву», может быть и несколькими символами
(буква с отдельным значком ударения, флаг из двух символов), и это уже графемы, которые стандартная
библиотека не считает. Для проверок длины ввода выбирай осознанно: лимит на размер в хранилище считают байтами,
лимит «не больше 40 букв» считают `chars()`.

`char_indices()` отдаёт пары (байтовое смещение, символ), `char::len_utf8()` говорит, сколько байт займёт
символ. Индексы в `str` всегда байтовые.

## Границы символов

Срез `&s[a..b]` принимает только индексы на границах символов. Граница это начало любого символа и конец строки,
но не байт-продолжение. Нарушение это паника, а не ошибка:

```rust
let s = "Ёж ёлка";
let _ = &s[..1];     // паника: byte index 1 is not a char boundary (Ё занимает байты 0 и 1)
s.is_char_boundary(1)   // false
s.is_char_boundary(2)   // true
s.get(..1)              // None вместо паники
```

`get(range)` вместо индексации возвращает `Option`, а `is_char_boundary(i)` отвечает про один индекс за O(1).
Чтобы подрезать строку до лимита в байтах, отступай влево, пока индекс не окажется на границе. До границы
не больше трёх шагов. Резать «по `chars().take(n)`» тоже можно, но тогда лимит в символах, а не в байтах.

## Какие бывают проверки и преобразования символа

У `char` два набора методов: Юникодные (`is_alphabetic`, `is_alphanumeric`, `is_numeric`, `is_uppercase`,
`to_lowercase`) и ASCII (`is_ascii_alphabetic`, `is_ascii_digit`, `to_ascii_lowercase`). Первые узнают буквы всех
письменностей и странные цифры (арабо-индийские «٣», полноширинные «３»); вторые только `a-z`, `A-Z`, `0-9`. Для
идентификаторов, которые потом попадут в URL, имена файлов или командную строку, правильны ASCII-проверки. Для
человеческого текста (имя в профиле) юникодные.

Регистр в Unicode не сводится к «ячейка в ячейку». `char::to_lowercase` и `to_uppercase` возвращают
**итераторы**, потому что результат может состоять из нескольких символов (немецкая `ß` в верхнем регистре
это `SS`), а длина в байтах может поменяться (турецкая `İ` в нижнем регистре превращается в две буквы).
Из этого следует правило: смещения, посчитанные в строке после смены регистра, нельзя применять к оригиналу.
Для сравнения без учёта регистра в ASCII есть `eq_ignore_ascii_case`: он ничего не копирует и не меняет длину.
`to_ascii_lowercase` трогает только ASCII-буквы и не зависит от версии таблиц Unicode, поэтому подходит для
ключей и сравнений протокола.

## Байты: &[u8], Vec<u8> и литералы

Когда данные не обязаны быть текстом (сеть, файлы, картинки), используют `&[u8]` и `Vec<u8>`. Литерал `b'x'`
это один `u8`, `b"abc"` это `&[u8; 3]`, а `b"\xff\x00"` позволяет записать любой байт.

```rust
let packet: &[u8] = b"WEIGHT 72\r\n";
packet.iter().position(|b| *b == b'\n')       // поиск байта
packet.strip_suffix(b"\r\n")                  // убрать хвост, Option<&[u8]>
packet.starts_with(b"WEIGHT")
packet.trim_ascii()                           // пробельные ASCII-байты по краям
b'q'.is_ascii_alphabetic(); b'q'.to_ascii_uppercase()   // методы u8
```

ASCII-методы у `u8` и срезов (`to_ascii_uppercase`, `eq_ignore_ascii_case`, `is_ascii_digit`) не трогают байты от
0x80 и выше, поэтому разбор протокола на байтах не портит чужие данные. Нужен текст из байт: `std::str::from_utf8`
(возвращает `Result<&str, Utf8Error>`) или `String::from_utf8` (владеющий вариант).

Для поиска в буфере есть `windows(n)` (скользящее окно) и `position`: `buf.windows(2).position(|w| w == b"\r\n")`.
Окно длиннее буфера просто даёт пустой итератор, паники нет. Срезы хороши ещё и тем, что ничего не копируют:
результат разбора это те же байты исходного буфера.

## Невалидный UTF-8

`from_utf8` не просто говорит «нет». `Utf8Error` хранит два числа:

```
valid_up_to()  длина правильного начала: &bytes[..n] точно валидная строка
error_len()    Some(k): здесь k неправильных байт (мусор);
               None:    байты кончились посреди символа (возможно, остаток ещё придёт)
```

Различие `Some` и `None` это развилка протокола: «подождать» или «отвергнуть». Есть и вариант «не страдать»:
`String::from_utf8_lossy(bytes)` заменяет мусор символом U+FFFD (`�`). Для логов годится, для данных нет: информация
потеряна необратимо.

Сеть режет поток как попало, и граница куска вполне может попасть внутрь символа. Декодер, который
переваривает куски по отдельности, портит такие символы. Правильный декодер хранит хвост (не больше трёх
байт) до следующего куска:

```
кусок 1: [.. D0]       валидное начало отдаём, D0 откладываем (error_len == None)
кусок 2: [B9 ..]       приписываем к отложенному: D0 B9 это «й», отдаём
```

А если `error_len` равен `Some(k)`, это настоящий мусор: заменяем и идём дальше.

## Числа из байт

Разбор числа руками быстрее и строже, чем через `String`. Цифра ASCII это `b - b'0'` (если `b.is_ascii_digit()`).
Накапливать число нужно **проверяемой** арифметикой, иначе длинная строка цифр переполнит тип:

```rust
let mut n: u32 = 0;
for &b in digits {
    if !b.is_ascii_digit() { return None; }
    n = n.checked_mul(10)?.checked_add(u32::from(b - b'0'))?;
}
```

Стандартный `str::parse` принимает знак `+`; в протоколах, где два участника читают одно число, любая
«щедрость» одного из них это лазейка. Шестнадцатеричные цифры
даёт `char::from(b).to_digit(16)`: он принимает только ASCII-цифры и буквы a-f любого регистра, без знака.

## Биты, сдвиги и маски

```rust
flags & MASK != 0          // стоит ли бит (или любой из набора)
flags | MASK               // поставить
flags & !MASK              // снять
(flags & MASK) >> 4        // достать поле из середины
(flags & !MASK) | value    // заменить поле: сначала стереть, потом записать
```

Три ловушки. Первая: **расширяй до сдвига**. `b << 8` для `b: u8` теряет все биты (сдвиг на 8 для `u8` вообще
отвергается), нужно `u16::from(b) << 8`. Вторая: **приоритеты**. `<<` слабее `+`, поэтому `a << 8 + b` это
`a << (8 + b)`, а не то, что хотелось. Пиши скобки. Третья: сдвиг на ширину типа и больше (`1u32 << 32`)
паникует в отладке; для границ есть `checked_shl`, возвращающий `None`. Приведение `as i8 as u32` расширяет со
знаком и заполняет старшие биты единицами: расширять беззнаковые значения нужно через `u32::from`.

## Порядок байт и сужающие преобразования

Число из нескольких байт можно записать старшим байтом вперёд (big-endian, «сетевой порядок») или младшим
(little-endian). Имена методов говорят об этом прямо:

```rust
u32::from_be_bytes([0, 0, 1, 2])   // 258
u32::from_le_bytes([0, 0, 1, 2])   // 33619968
258u32.to_be_bytes()               // [0, 0, 1, 2]
```

Из среза в массив нужной длины помогает `try_into`: `let arr: [u8; 4] = buf[..4].try_into()?;` Сначала взять срез
безопасно: `buf.get(a..b)` вернёт `None` на коротком буфере, а `buf[a..b]` паникует. Смещение, пришедшее извне,
складывай проверяемо (`checked_add`), иначе оно переполнится.

Оператор `as` между целыми **не проверяет** и не предупреждает: `70_000usize as u16` это 4464 (младшие 16 бит).
В протоколе так в заголовок попадает длина, которая врёт. Вместо этого `u16::try_from(len)`: он вернёт ошибку,
если число не помещается, и ошибку можно показать там, где её ещё можно исправить. Расширяющие преобразования
безопасны и пишутся `u32::from(x)`.

## Форматирование

Спецификатор в `{}` читается слева направо: `{имя:заполнитель выравнивание знак # 0 ширина .точность тип}`.

```
{:<8}  влево в 8      {:>8} вправо      {:^8} по центру      {:*^8} по центру, заполнитель *
{:.2}  у числа два знака после запятой; у строки не больше двух символов (обрезка!)
{:08.3} нули слева      {:+} знак      {:#x} 0xff      {:#010b} 0b00000101 (ширина считает префикс)
{:x} {:X} {:o} {:b} {:e}   шестнадцатеричное, восьмеричное, двоичное
```

Свой тип получает `Display` через `impl fmt::Display`, но `write!(f, ..)` игнорирует ширину и выравнивание, которые
запросил вызывающий. Чтобы тип вёл себя как встроенные, готовую строку отдают через `f.pad(&text)`.

`write!` работает с любым приёмником: `String` (трейт `fmt::Write`), `Vec<u8>`, файлом или сокетом (трейт
`io::Write`). Собрать ответ из текстового заголовка и бинарного тела удобно прямо в `Vec<u8>`: `write!(out, "..")`
для заголовка и `out.extend_from_slice(body)` для тела. Строить для каждой части временную строку через `format!`
и тут же её добавлять расточительно.

## Курсор по байтам: «мало данных» и «битые данные»

Парсер протокола идёт по буферу слева направо и на каждом шаге спрашивает, хватает ли байт. Если не хватает, это
не ошибка в данных: поток просто не дошёл, нужно дочитать сокет и повторить. Если же данные пришли и они неверны
(неизвестный вид, длина выше предела, не UTF-8), ждать бессмысленно. Это два разных исхода, и смешивать их нельзя:

```
Incomplete { needed }   мало: подожди и попробуй снова с того же места
Invalid(причина)        битые: ничего не исправит, закрывай соединение
```

Хороший парсер: никогда не паникует на коротком буфере (используй `get`, а не индексы); не двигает позицию
при неудаче (повтор начнётся с того же места); отвергает мусор **как только понял, что это мусор** (по первому
байту, по заголовку), не дожидаясь остального; слишком большую заявленную длину отвергает сразу, иначе злоумышленник
заставит копить мегабайты на каждое соединение; сообщает, сколько байт ещё нужно хотя бы.

## Типичные ошибки

- Резать строку по байтовому индексу, пришедшему из данных (`&s[..n]`).
- Путать `len()` с числом символов и считать лимит «в буквах» в байтах (или наоборот).
- Применять смещения из `to_lowercase()` к исходной строке.
- Считать `is_alphanumeric` проверкой для идентификатора (она пускает «１２» и «٣»).
- Декодировать куски потока по отдельности через `from_utf8_lossy`.
- Собирать бинарный ответ через `String`.
- Парсить длины через `str::parse` и `as`, терять переполнение.
- Сдвигать `u8` на 8 бит, забывать скобки вокруг `<<`.
- Называть любую нехватку байт ошибкой данных и наоборот.
