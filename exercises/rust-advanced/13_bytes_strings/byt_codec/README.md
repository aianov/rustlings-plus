# Проект: бинарный кодек сообщений чата

Чат переезжает с JSON на компактный бинарный формат: сообщение в нём короче в два-три раза, а разбор
не требует выделять память на каждое поле. Но байты по сети приходят кусками как попало, текст в сообщениях
на любых языках с эмодзи, а злоумышленник может прислать что угодно. Крейт `chat-codec` это кодек, поток
для сборки сообщений из кусков, отладочный `hexdump` и аккуратное превью текста. Только `std`.

## Формат сообщения

```
байт 0        флаги: бит 0 EDITED (1), бит 1 REPLY (2), бит 2 SILENT (4); биты 3..=7 равны нулю
байты 1..=2   длина текста в байтах, u16, старший байт первым; не больше 4096
[байты 3..=6] reply_to, u32 в том же порядке; есть только если выставлен флаг REPLY
дальше        текст в UTF-8
```

## Что нужно сделать

В `crates/chat-codec/src/lib.rs` объявлены типы и сигнатуры, тела пустые.

1. `encode(&Message)`: описанный формат. Ошибки: `UnknownFlags(флаги)` (лишние биты), `ReplyMismatch`
   (флаг REPLY и `reply_to` не согласованы: одно есть, другого нет), `TooLong(длина в байтах)` для текста
   длиннее 4096 байт. Длина считается в байтах, не в символах.
2. `decode(buf)` возвращает сообщение и число прочитанных байт, лишние байты после него игнорирует.
   Ошибки: `Incomplete { needed }` (байт не хватает; до заголовка нужно хотя бы 3, потом сколько нужно до
   конца сообщения), `UnknownFlags` (по первому байту, не дожидаясь остального), `TooLong` (по заголовку),
   `BadUtf8` (весь текст на месте, но это не UTF-8). Паники исключены на любом входе.
3. `Stream` собирает сообщения из кусков: `feed(&[u8])` добавляет, `next_message()` возвращает
   `Ok(Some(msg))`, если целое сообщение собралось, `Ok(None)`, если ещё нет, `Err`, если данные битые.
   Прочитанные байты из буфера убираются. `buffered()` сколько байт лежит в буфере. Разрезанные посередине
   буквы и поля не мешают.
4. `hexdump(bytes)`: по 16 байт в строке. Строка: смещение из 8 строчных шестнадцатеричных цифр, два пробела,
   16 ячеек по три символа (`xx ` или три пробела для отсутствующих), затем `|` и печатный ASCII (остальные байты
   как точка) и `|`, перевод строки. Пустой ввод даёт пустую строку.
5. `preview(text, max_bytes)`: текст не длиннее лимита возвращается как есть, иначе самое длинное начало
   по границе символа плюс `…`, так чтобы всё вместе уложилось в `max_bytes` байт. Меньше трёх байт: пусто.

## Как проверить

```
cargo test --workspace
```

Приёмочные тесты лежат в `crates/chat-codec/tests/acceptance.rs`, их менять нельзя.
