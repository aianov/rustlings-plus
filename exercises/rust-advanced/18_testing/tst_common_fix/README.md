# Проект: потерявшиеся помощники

Крейт `billing` считает счета. В `crates/billing/tests/` лежат два файла тестов и общий файл с помощниками.
Разработчик положил помощников в `tests/common.rs`, как делают с обычным модулем, и получил сразу две
беды. Во-первых, в выводе `cargo test` появился лишний пустой запуск `running 0 tests` (cargo собрал
`common.rs` как самостоятельный тестовый крейт). Во-вторых, тесты не собираются: помощники объявлены без
`pub`, и соседние файлы их не видят.

## Что нужно сделать

1. Перенеси помощников туда, где cargo не примет их за тест, и подключи так, чтобы оба файла
   (`totals.rs`, `discounts.rs`) продолжали видеть их через `mod common;`.
2. Сделай помощников видимыми для соседей.
3. Прогон должен быть без предупреждений: каждому файлу нужна лишь часть помощников, и компилятор ворчит
   на остальные. Придумай, как объяснить ему, что так и задумано, одной строкой и в правильном месте.
4. Сами тесты и код библиотеки не трогай: все шесть тестов должны остаться и пройти. Помощников
   копировать в каждый файл нельзя.

## Как проверить

```
cargo test --manifest-path acceptance/Cargo.toml
```

Обычный `cargo test --workspace` покажет то же самое подробнее: в нём не должно быть строки с `common`,
предупреждений, а тестовых крейтов должно быть ровно два. Приёмочные тесты в `acceptance/` менять нельзя.
