# Проект: покрываем ленту

Библиотека `feedlib` это ядро ленты постов: публикация с проверками и паузой между постами одного автора,
страницы «сначала новые» с курсором и фильтром по автору, короткая сводка. Код готов, тестов в нём нет.
Нужно написать все виды тестов, которые знаешь, так, чтобы любая будущая правка, ломающая поведение, была
заметна. Про сами тесты проверяет приёмка: она подсовывает в библиотеку двенадцать разных поломок, и набор
обязан краснеть на каждой.

## Правила ленты

Автор и текст непусты после очистки. Очистка текста: убрать управляющие символы кроме перевода строки,
обрезать края. Длина считается в символах, `MAX_CHARS` включительно, длиннее это `TooLong(длина)`.
Один автор не публикует чаще, чем раз в `COOLDOWN_SECS` секунд: слишком рано это `TooFast { wait }`, где
`wait` сколько секунд осталось ждать. Номера постов идут с 1. `page` отдаёт новые посты первыми, `before`
исключает пост с этим номером и все более поздние, автор в фильтре сравнивается без учёта регистра.

## Что нужно сделать

1. Юнит-тесты внутри `crates/feedlib/src/lib.rs`, в `#[cfg(test)] mod tests`: не меньше четырёх, среди них
   проверка приватной функции `clean`. Часы там нужны свои, подставные (`impl Clock for ...`).
2. Интеграционные тесты в `crates/feedlib/tests/`: не меньше двух файлов (по два теста и больше в каждом),
   подставные часы с возможностью сдвигать время в `tests/common/mod.rs`.
3. Документационные примеры у `publish` и `page`: два теста, которые проверяют результат.
4. В тестах нет настоящего времени и ожиданий (`SystemTime`, `Instant::now`, `sleep`).
5. Тесты не зависят друг от друга: набор зелёный при `--test-threads=1` и при `--test-threads=8`,
   предупреждений нет.
6. Рабочий код библиотеки не меняй: приёмка ищет в нём конкретные строки.

## Как проверить

```
cargo test --manifest-path acceptance/Cargo.toml
```

Приёмочные тесты в `acceptance/` менять нельзя. Для работы удобнее `cargo test -p feedlib`.
