# build.rs: код, который пишет код

Если рядом с `Cargo.toml` лежит файл `build.rs`, cargo сначала компилирует и запускает его, и только
потом собирает сам пакет. Скрипт может подготовить данные, сгенерировать исходники или передать в
сборку значения.

Здесь словарь для проверки орфографии хранится обычным текстом в `data/words.txt` (с комментариями,
пустыми строками и повторами), а в программу должен попасть готовый отсортированный массив.

## Что сделать

1. `build.rs`: прочитай `data/words.txt`, очисти, отсортируй, запиши в `$OUT_DIR/words.rs`
   константу `pub const WORDS: &[&str]`.
2. `build.rs` печатает управляющие строки для cargo:
   - `cargo::rerun-if-changed=data/words.txt`;
   - `cargo::rustc-env=WORDLIST_BUILD=wordlist 0.3.0 (5 words)`. Версию бери из переменной
     окружения `CARGO_PKG_VERSION`, число слов считай.
3. `src/lib.rs`: подключи сгенерированный файл через `include!` и путь из `env!("OUT_DIR")`,
   объяви `pub const BUILD: &str = env!("WORDLIST_BUILD");`.

Генерировать файлы в `src/` нельзя: исходники принадлежат человеку, а не сборке.

## Приёмка

```
cargo test
cargo run
```
