# Когда cargo перезапускает build.rs

Меню кофейни лежит в `data/items.txt`, а `build.rs` превращает его в таблицу `ITEMS`. Работает,
пока не начнёшь это меню править: программа живёт со старой таблицей, а в `src/` после сборки
появляется лишний файл.

Правило такое. Без единой строки `cargo::rerun-if-changed` cargo перезапускает скрипт, когда меняется
любой файл пакета. Как только такая строка появилась, cargo следит только за указанными путями.
Строка `rerun-if-changed=build.rs`, скопированная из примера, говорит «следи за самим скриптом» и
больше ни за чем, поэтому правка данных остаётся незамеченной. Ещё скрипт сборки не должен писать в
исходники пакета: они принадлежат человеку, а сгенерированное лежит в отведённом сборке месте.

## Что сделать

1. Исправь `cargo::rerun-if-changed`: он должен следить за файлом с данными (за скриптом тоже можно).
2. Скрипт не должен оставлять следов в `src/`. Из `lib.rs` при этом исчезает `mod generated;`.

## Приёмка

Тесты копируют проект во временную папку и там проверяют три вещи: `src/` остался чистым, повторная
сборка без изменений `Fresh`, а правка `data/items.txt` меняет вывод программы.

```
cargo test
cargo build -v      # два раза подряд: во второй должно быть Fresh
```
