# Проект: язык контрактов сервисов

В соцсети появилось несколько сервисов, и у каждого свой набор методов: имя в протоколе (`users.follow`),
тип запроса и тип ответа. Список методов дублируется в трёх местах: в enum для `match`, в таблице для
маршрутизатора, в проверке неизвестных имён. Добавили метод в одно место и забыли другое, получили 404 в
проде. Нужен один макрос `service!` в общем крейте `contracts`: метод описывается одной строкой, остальное
макрос раскрывает сам. Им пользуются два сервиса, `user-service` и `post-service` (их код уже написан и
менять его не нужно).

## Как выглядит вызов

```rust
contracts::service! {
    /// Методы сервиса пользователей.
    pub enum UserMethod {
        Register = "users.register" (RegisterRequest) -> RegisterResponse,
        Follow = "users.follow" (FollowRequest) -> Empty,
    }
}
```

## Что должен давать макрос

1. Сам enum с теми же атрибутами и видимостью, как в вызове, и с `Debug, Clone, Copy, PartialEq, Eq, Hash`.
2. `ALL: &'static [Enum]` с вариантами в порядке записи (константа).
3. `ROUTES: &'static [contracts::Route]`: по записи на метод, `Route { name, request, response }`, где `request` и
   `response` это названия типов в виде текста (`"RegisterRequest"`). Константа.
4. `name(self) -> &'static str`, `request_type(self)`, `response_type(self)`, `from_name(&str) -> Option<Enum>`.
5. `duplicates() -> Vec<&'static str>`: имена методов, записанные больше одного раза (каждое один раз, в порядке
   первой повторной записи). Для корректных сервисов список пуст.
6. Типы запроса и ответа должны существовать: опечатка в имени типа ломает сборку, а не обнаруживается потом.
7. Допустимы запятая после последнего метода и любые типы в скобках (`Page<Post>`).

В `crates/contracts/src/lib.rs` уже есть `Route` и `find_duplicates`. Нужно написать `service!`.

## Как проверить

```
cargo test --workspace
```

Приёмочные тесты лежат в `crates/*/tests/acceptance.rs`, менять их нельзя. Тесты сервисов проверяют, что оба
пользуются макросом из `contracts`, а тесты `contracts` проверяют само поведение макроса на разных вызовах.
