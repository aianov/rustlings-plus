# Проект: типобезопасное ядро API

Соцсеть растёт, и в коде одновременно ходят id пользователей, id постов, суммы в копейках и строки
запроса вроде `page=3&author=u_9`. Любую путаницу между ними хочется ловить при сборке, а не в логах.
В библиотеке `typed-api` собери пять кирпичей, которые ты разобрал в главе.

## Что нужно сделать

В `src/lib.rs` объявлены типы и сигнатуры, тела пустые.

1. `Id<T>`: число с типом-владельцем. `new`, `raw`. Копируется, сравнивается и хешируется по числу
   при любом `T`, `Debug` печатает `Id(7)`. Свойства `T` на `Id<T>` не влияют (даже `Id<Rc<u8>>` это
   `Send + Sync`). Для `T: Kind` `Display` печатает `u_42` (префикс из `Kind::PREFIX`), а `FromStr`
   разбирает такую строку: другой префикс это `IdError::WrongPrefix`, мусор вместо числа `IdError::BadNumber`.
2. `Money` в копейках: сложение, умножение на `u32`, `Sum`, `checked_sub` (меньше нуля не бывает),
   `Display` вида `12.34`.
3. `Table<T>`: `insert` выдаёт `Id<T>` с единицы подряд, `get` принимает только `Id<T>`; нулевой и
   неизвестный номер дают `None`. Для `T: Kind` есть `lookup(query, key)`: достать `Id<T>` из строки запроса
   через `param` (см. пункт 5) и найти строку. Нет ключа или неизвестный номер: `Ok(None)`; плохой id: ошибка `param`.
4. `PostDraft<A, T>`: черновик поста с состояниями `Missing`/`Set` для автора и текста. Сеттеры в любом
   порядке, `boost` необязателен и состояния не меняет. `build()` существует только у `PostDraft<Set, Set>`
   и возвращает `Option<NewPost>`.
5. `param::<T>(query, key)`: найти `key` в строке `a=1&b=2` и разобрать значение через `FromStr`.
   Нет ключа: `Ok(None)`. Ошибка разбора: `ParamError { key, reason }`, где `reason` это текст ошибки
   разбора. Работает для любого `T` с `FromStr`, в том числе для `Id<User>`.

## Как проверить

```
cargo test
cargo clippy --all-targets -- -D warnings
```

## Подсказки по теории

Clippy потребует `Default` для `Table::new`: пиши его вручную, `derive(Default)` потянет за собой
`T: Default`, то есть ту самую ловушку главы. Свойства `Id<T>` реализуй вручную (derive потребует их от `T`), а маркер храни как
`PhantomData<fn() -> T>`. Для `param` ограничения нужны и на `T`, и на `T::Err`. Состояния
построителя это параметры типа, сеттер возвращает builder с другим значением параметра.
