# Веха 1. Пользователь и пост

Любая соцсеть начинается с двух вещей: человека и того, что он написал. Сервера у нас нет, базы нет, даже второго файла нет. Зато ты уже умеешь структуры и перечисления, а этого хватит, чтобы описать главных героев. Всё, что появится здесь, доживёт до последней главы курса: оно переедет в другие папки, обрастёт проверками и базами, но `User` и `Post` останутся теми же.

Проект живёт в папке `backend/`. Курс уже положил туда `Cargo.toml` и заготовку `src/lib.rs`, а в `src/tests/` лежат приёмочные тесты. Тесты не правь: перед каждой проверкой курс кладёт их заново.

## Что сделать

Весь код пиши в `src/lib.rs`. Слово `pub` пока не нужно: тесты живут внутри крейта и видят всё.

1. `UserId` и `PostId`: кортежные структуры с одним полем `u64`. Над каждой поставь `#[derive(Debug, Clone, Copy, PartialEq, Eq)]`. `Clone, Copy` делают id копируемым, как обычное число (присваивание не перемещает значение), а `PartialEq, Eq` разрешают сравнивать через `==`.
2. `User` с полями `id: UserId`, `name: String`, `bio: String` и методами:
   - `fn new(id: UserId, name: String) -> User`, био у нового пользователя пустое;
   - `fn id(&self) -> UserId`, `fn name(&self) -> &str`, `fn bio(&self) -> &str`;
   - `fn rename(&mut self, name: String)` и `fn set_bio(&mut self, bio: String)`.
3. `Visibility`: перечисление `Public`, `Followers`, `Private` с тем же derive, что у id.
4. `PostKind`: варианты `Text` и `Repost(PostId)`, внутри репоста id исходного поста. Derive тот же.
5. `Post` с полями: id (`PostId`), автор (`UserId`), текст (`String`), вид (`PostKind`), видимость (`Visibility`), счётчик лайков (`u32`). Методы:
   - `fn new(id: PostId, author: UserId, text: String, visibility: Visibility) -> Post`: текстовый пост без лайков;
   - `fn repost(id: PostId, author: UserId, original: PostId) -> Post`: репост с пустым текстом, виден всем;
   - `fn id(&self) -> PostId`, `fn author(&self) -> UserId`, `fn text(&self) -> &str`,
     `fn kind(&self) -> PostKind`, `fn visibility(&self) -> Visibility`, `fn likes(&self) -> u32`;
   - `fn like(&mut self)`: плюс один лайк;
   - `fn is_repost(&self) -> bool`;
   - `fn can_view(&self, viewer: UserId, follows_author: bool) -> bool`: правило видимости, написанное через `match`.

Правило видимости:

| видимость   | кто видит пост               |
|-------------|------------------------------|
| `Public`    | все                          |
| `Followers` | автор и его подписчики       |
| `Private`   | только автор                 |

Подписок у нас ещё нет, поэтому ответ на вопрос «подписан ли зритель на автора» `can_view` получает готовым, в `follows_author`.

## Дерево после вехи

```
backend/
  Cargo.toml              из заготовки
  src/
    lib.rs                весь код вехи
    tests/                тесты курса, не правь
      mod.rs
      m01_user_post.rs
```

Других файлов в `src/` пока не заводи: одному файлу на этом этапе очень даже хорошо.

## Приёмка

- `src/tests/m01_user_post.rs`: id копируются и сравниваются, пользователь создаётся, переименовывается и меняет био, новый пост без лайков, лайки копятся, репост помнит исходный пост, видимость работает по таблице.
- Архитектура: есть `Cargo.toml` и `src/lib.rs`; в `src/lib.rs` на месте строка `mod tests;` (без неё тесты курса не попадут в сборку, и проверка пройдёт впустую); в `src/` модули одного вида.

## Как запустить

```
cd backend
cargo test
```

Пока тип не описан, тесты даже не скомпилируются. Это нормально: читай первую ошибку компилятора, описывай тип, на который он жалуется, и иди к следующей.
