# Веха 6. Много потоков, одна сеть

Пока соцсетью пользовался один человек за раз, `&mut Network` хватало. Но настоящие пользователи не встают в очередь: десять человек одновременно пишут посты, лайкают и подписываются. Каждому нужен свой поток, а сеть у всех одна. Отдать десяти потокам `&mut` компилятор не разрешит, и правильно сделает: так теряются лайки и ломаются индексы. Значит, сеть надо положить под замок и раздать потокам ручки к ней.

Вторая новость: люди хотят знать, что их лайкнули. Писать уведомления прямо внутри лайка можно, но тогда лайк ждёт, пока уведомление дойдёт. Лучше так: операция бросает событие в канал и сразу возвращается, а отдельный фоновый поток читает канал и раскладывает уведомления по ящикам. Почтальон, а не курьер под дверью.

И мелочь, приятная для памяти: `normalize_name` больше не создаёт новую строку, если ник уже нормальный.

## Что сделать

1. `domain/user.rs`: `pub fn normalize_name(name: &str) -> Cow<'_, str>`. Если в нике после `trim` нет заглавных букв, отдай `Cow::Borrowed` (кусок исходной строки, без аллокации), иначе `Cow::Owned` с нижним регистром. Остальной код почти не заметит разницы: `Cow<str>` разыменовывается в `&str`.
2. `src/notify/mod.rs`: уведомления и фоновый поток.
   - `pub enum Notification { Followed { by: UserId }, Liked { by: UserId, post: PostId } }` с derive `Debug, Clone, Copy, PartialEq, Eq`;
   - события, которые операции отправляют в `std::sync::mpsc`-канал, и фоновый поток, который читает канал и складывает уведомления в ящики: у каждого пользователя свой `Vec<Notification>` в порядке прихода;
   - поток запускается через `std::thread::Builder::new().name(String::from("notify")).spawn(...)`. Это тот же `thread::spawn`, только поток получает имя (его видно в отладчике и в сообщении о панике), а неудача запуска приходит как `io::Error`, а не паникой: ОС может и не дать новый поток;
   - поток живёт, пока жив хотя бы один отправитель канала.
3. `src/shared/mod.rs`: `pub struct SharedNetwork<U, P>`, клонируемая ручка: внутри `Arc<Mutex<Network<U, P>>>` и отправитель канала уведомлений. Клон ручки смотрит на ту же сеть. Методы (все берут `&self`):
   - `pub fn new(network: Network<U, P>) -> std::io::Result<SharedNetwork<U, P>>`: забирает сеть и запускает фоновый поток уведомлений; ошибку запуска потока пробрось через `?`;
   - `register`, `publish`, `follow`, `like` с теми же аргументами и `Result`, что у `Network`;
   - `follow`, если подписка новая (`Ok(true)`), шлёт событие: в ящик тому, на кого подписались, ляжет `Followed { by: кто_подписался }`;
   - `like`, если лайк новый и лайкнул не сам автор, шлёт событие: автору поста ляжет `Liked { by, post }`;
   - `pub fn read<R>(&self, f: impl FnOnce(&Network<U, P>) -> R) -> R`: даёт замыканию посмотреть на сеть под замком (ленту, счётчики, поиск);
   - `pub fn inbox(&self, user: UserId) -> Vec<Notification>`: копия ящика. Важно: в ящике уже должно быть всё, что отправили до вызова `inbox`. Фоновый поток мог ещё не успеть, поэтому `inbox` сначала дожидается его.
4. `SharedNetwork<MemUserStore, MemPostStore>` можно передать в другой поток (`Send + Clone + 'static`). `#[derive(Clone)]` тут не подойдёт: он потребует `U: Clone` и `P: Clone`, хотя клонируем мы только `Arc`. Напиши `impl<U, P> Clone` руками.
5. `Network` остаётся обычной однопоточной структурой: в `domain/`, `network/`, `ports/` и `storage/` нет `std::sync`. Потоки живут только в `shared/` и `notify/`. `static mut` не используем нигде.
6. Если поток с замком упал, `lock()` вернёт ошибку `PoisonError`. `unwrap()` по-прежнему нельзя: забери данные через `.unwrap_or_else(PoisonError::into_inner)`.

Как дождаться почтальона. Сообщения в одном канале приходят в том порядке, в каком их отправили. Значит, можно отправить в тот же канал особое сообщение «отметься» вместе с одноразовым каналом для ответа. Когда поток ответил, всё отправленное раньше уже разложено:

```
поток операции           канал               фоновый поток
like ──── Liked ───────> [Liked]  ─────────> ящик alice += Liked
inbox ─── Flush(tx) ───> [Flush]  ─────────> tx.send(())
      <──────────────────── () ─────────────
читаем ящик alice: Liked уже там
```

```

  Cargo.toml
  src/
    lib.rs                + mod notify; mod shared; pub use Notification, SharedNetwork
    domain/   mod.rs  error.rs  user.rs (Cow)  post.rs
    network/  mod.rs  feed.rs  follows.rs  tags.rs
    notify/
      mod.rs              Notification, события, фоновый поток и ящики
    ports/    mod.rs
    shared/
      mod.rs              SharedNetwork
    storage/  mod.rs  users.rs  posts.rs
  tests/                  тесты курса, не правь
    m01_user_post.rs ... m05_feed.rs
    m06_shared_threads.rs
```

## Приёмка

- `tests/m06_shared_threads.rs`: `normalize_name` отдаёт `Borrowed` без нужды в аллокации и `Owned` при заглавных; ручка уходит в другой поток; клоны видят одну сеть; подписка и лайк кладут уведомления в нужный ящик, повторы и свой лайк не шлют; `inbox` видит всё отправленное до него (200 подписчиков и 200 лайков подряд); десять потоков одновременно регистрируются, постят, подписываются и лайкают, и ни один лайк, подписка или уведомление не теряются.
- Архитектура: всё из прошлых вех, плюс есть `src/shared/mod.rs` и `src/notify/mod.rs`; в `notify/` есть `mpsc` и запуск потока; `std::sync` только в `shared/` и `notify/`; нигде нет `static mut`.
