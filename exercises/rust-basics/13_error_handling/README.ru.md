# Обработка ошибок

Большинство ошибок не настолько серьёзны, чтобы программа должна полностью остановиться.
Иногда функция проваливается по причине, которую легко понять и на которую легко
отреагировать. Например, если ты пытаешься открыть файл, а его нет, можно создать
этот файл, а не завершать процесс.

## Кратко

Ошибки, которые можно обработать, в Rust возвращаются как `Result<T, E>`: либо `Ok(значение)`,
либо `Err(ошибка)`. Исключений нет, поэтому по сигнатуре видно, что функция может провалиться.

```rust
fn parse_age(s: &str) -> Result<u8, std::num::ParseIntError> {
    let age: u8 = s.parse()?; // при ошибке сразу вернётся Err
    Ok(age)
}
```

Оператор `?` разворачивает `Ok` или досрочно возвращает `Err` из функции, при необходимости
преобразуя ошибку через `From`. Из `main` тоже можно вернуть `Result`. Когда в одной функции
встречаются разные типы ошибок, подойдёт `Box<dyn Error>`; в библиотеках лучше заводить свой
`enum` ошибок, чтобы вызывающий мог на него `match`иться. `map_err` меняет тип ошибки,
`unwrap` и `expect` паникуют, поэтому оставляй их для тестов и «невозможных» случаев.
