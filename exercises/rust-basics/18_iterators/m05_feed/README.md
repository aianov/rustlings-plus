# Веха 5. Лента

Зачем вообще заходить в соцсеть? Чтобы открыть ленту и увидеть, что написали те, на кого ты подписан. У нас уже есть всё для неё: посты в хранилище по порядку публикации, подписки, правило видимости. Осталось собрать это в одну цепочку: взять все посты, развернуть (новые сверху), оставить свои и чужие от подписок, выкинуть то, что зрителю не положено видеть, и отрезать первые N. Ровно так и читается цепочка итераторов, по шагу на строку.

Лента отдаёт ссылки на посты, которые лежат в хранилище. Никаких копий: пост может быть длинным, а лента большой, и копировать всё ради показа незачем. Компилятор сам проследит, чтобы ссылки не пережили сеть, из которой их взяли.

И ещё одно: с этой вехи ты пишешь свои тесты. Тесты курса проверяют снаружи, а свои тесты рядом с кодом ловят то, что важно тебе.

## Что сделать

1. `src/network/feed.rs`: ещё один блок `impl<U: UserStore, P: PostStore> Network<U, P>` с методами ленты. Модуль `feed` дочерний для `network`, поэтому видит приватные поля `Network`. Подключи его строкой `mod feed;` в `network/mod.rs`.
2. `pub fn feed(&self, viewer: UserId, limit: usize) -> Vec<&Post>`: посты самого зрителя и тех, на кого он подписан; только те, что ему видны (`can_view`); новые сверху; не больше `limit`. У незнакомого id лента пустая.
3. `pub fn search_tag(&self, viewer: UserId, tag: &str) -> Vec<&Post>`: все посты с тегом, которые зрителю видны (подписка тут не нужна, но правило видимости действует); новые сверху. Тег принимается как в `posts_with_tag`.
4. Счётчики по автору: `pub fn post_count_of(&self, author: UserId) -> usize` и `pub fn likes_received(&self, author: UserId) -> usize` (сумма лайков всех его постов).
5. Всё это итераторами: `iter`, `rev`, `filter`, `filter_map`, `map`, `take`, `count`, `sum`, `collect`. В `feed.rs` нет `.clone()`: лента собирает ссылки, а не копии.
6. В `feed.rs` модуль `#[cfg(test)] mod tests` с твоими тестами (хотя бы одним). Что проверить, решай сам: например, ленту без подписок или незнакомого зрителя. `unwrap()` нельзя и в тестах внутри `src/`, используй `expect("что пошло не так")`.

Цепочка ленты, если нарисовать:

```
all()           [p1 p2 p3 p4 p5 p6 p7]     порядок публикации
.rev()          [p7 p6 p5 p4 p3 p2 p1]     новые сверху
.filter(...)    [p7 p6 p5 p2 p1]           свои и подписки, только видимые
.take(limit)    [p7 p6]                    limit = 2
.collect()      Vec<&Post>
```

## Дерево после вехи

```
backend/
  Cargo.toml
  src/
    lib.rs
    domain/   mod.rs  error.rs  user.rs  post.rs
    network/
      mod.rs              + mod feed;
      feed.rs             лента, поиск, счётчики и твои тесты
      follows.rs  tags.rs
    ports/    mod.rs
    storage/  mod.rs  users.rs  posts.rs
  tests/                  тесты курса, не правь
    m01_user_post.rs  m02_follow_graph.rs  m03_domain_errors.rs  m04_store_traits.rs
    m05_feed.rs
```

## Приёмка

- `tests/m05_feed.rs`: лента из своих постов и подписок, новые сверху, с лимитом и видимостью; незнакомому зрителю пустая; лента отдаёт ссылки прямо в хранилище (проверяется через `std::ptr::eq`); поиск по тегу с видимостью; счётчики постов и лайков.
- Твои тесты в `src/network/feed.rs` тоже запускаются и должны проходить.
- Архитектура: всё из прошлых вех, плюс есть `src/network/feed.rs` с `#[cfg(test)]` и без `.clone()`.

## Как запустить

```
cd backend
cargo test
```

Только свои тесты ленты: `cargo test feed::tests`.
