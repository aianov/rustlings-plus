# Времена жизни

Времена жизни подсказывают компилятору, как проверить, что ссылки живут достаточно долго
и остаются корректными в любой ситуации. Например, они говорят: «убедись, что параметр 'a
живёт не меньше, чем параметр 'b, чтобы возвращаемое значение было валидным».

Они нужны только для заимствований, то есть ссылок: скопированные или перемещённые
параметры принадлежат своей области видимости, и на них нельзя сослаться снаружи.
Благодаря временам жизни код, вызывающий функции, можно проверить на корректность
аргументов. Времена жизни накладывают ограничения на вызывающих.

Если хочешь больше узнать про аннотации времён жизни, у проекта
[lifetimekata](https://tfpk.github.io/lifetimekata/) похожий на Rustlings формат упражнений,
но целиком посвящённый тому, как писать такие аннотации.

## Кратко

Ссылка не может пережить то, на что она указывает. Обычно компилятор сам понимает сроки жизни,
но когда функция принимает несколько ссылок и возвращает одну, ему нужна подсказка: чьё время жизни
у результата.

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

struct Book<'a> {
    title: &'a str,
}
```

`'a` не продлевает жизнь данных, а лишь связывает сроки: результат живёт не дольше самой короткой
из входных ссылок. Если структура хранит ссылку, у неё тоже появляется параметр времени жизни.
Ошибку «borrowed value does not live long enough» чаще всего чинят так: переносят объявление
значения выше или используют результат раньше, пока владелец ещё жив.
