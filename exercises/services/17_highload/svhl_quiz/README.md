# feed-service: лента, которая выдерживает нагрузку

Соцсеть растёт: у одних авторов десятки подписчиков, у других миллионы, ленту открывают чаще, чем пишут посты, и профили авторов запрашиваются тысячами в секунду.
Простой «собрать ленту запросом в базу» не вытягивает. Твоя часть: собрать `FeedService`, который использует приёмы главы: раскладку при записи с гибридом для знаменитостей,
курсоры, кэш профилей с вытеснением, разбросом срока жизни и общим вызовом на одинаковые промахи, пачки вместо N+1 и инвалидацию по событию. Проверка идёт против простой
модели и под параллельной нагрузкой.

## Как устроено

```
publish(автор, текст) ─► IdGen (сортируемый номер)
        │                    ├─ автор обычный:      номер дописывается в личную ленту каждого подписчика (не больше cap)
        │                    └─ автор знаменитость: номер кладётся один раз в общее хранилище автора (не больше cap)
feed(пользователь, курсор, limit)
        │   личная лента + хранилища знаменитостей, на которых подписан, слитые по номеру, строго старше курсора
        └─► Profiles::names(уникальные авторы страницы) ─► кэш (LRU, срок с разбросом) ─► один вызов Users::get_many
```

- `src/crates/feedsvc/src/ids.rs`, `cursor.rs`, `lru.rs`, `flight.rs`, `users.rs`: готовые кирпичи (генератор номеров, курсор, LRU, общий вызов, подмена user-service с задержкой).
- `src/crates/feedsvc/src/service.rs`: `FeedService` и `Profiles`. Заглушки `todo!()`: `Profiles::names`, `Profiles::invalidate`, `FeedService::publish`, `FeedService::feed`.
- `src/crates/feedsvc/tests/feed.rs`: приёмочные тесты. Править их нельзя, CLI восстанавливает их перед проверкой. Сеть и брокер не нужны.

## Что сделать

1. `Profiles::names`: живые имена из кэша; недостающие запрашиваются одним списком (по 100 за вызов), и одновременные запросы одного набора делят этот вызов; ответ кладётся в кэш со сроком `ttl_for`.
2. `Profiles::invalidate`: забыть имя.
3. `FeedService::publish`: сортируемый номер, раскладка или хранилище знаменитости (порог `celebrity_threshold`), обрезка до `cap`.
4. `FeedService::feed`: слить личную ленту с хранилищами знаменитостей, применить курсор и `limit` (от 1 до 50), подписать посты именами одним обращением к `Profiles::names`, выдать курсор только если дальше что-то осталось. Блокировку состояния нельзя держать через `.await`.

После работы `cargo test --workspace` проходит и `cargo clippy --workspace --all-targets -- -D warnings` чист.

## Критерии приёмки

- лента совпадает с простой моделью (все посты в одном списке) на 600 случайных шагах при любых размерах страницы;
- пост знаменитости не пишется в личные ленты, обычный автор раскладывается по подписчикам; лента обрезана до `cap`;
- 40 постов восьми авторов дают один вызов на восемь идентификаторов, повторный показ не ходит в user-service;
- тридцать одновременных одинаковых запросов с холодным кэшем делают один вызов; p99 при 64 параллельных лентах не больше 45 мс при задержке 20 мс;
- после события об изменении профиля запрашивается только изменившийся профиль; кэш ограничен ёмкостью, записи протухают в пределах плюс-минус 10% срока;
- сломанный курсор даёт ошибку, неизвестный автор подписывается «?».
