# Образ, который можно показать людям

Вот `Dockerfile` post-service, который кто-то написал за пять минут. Он собирается и запускается, и в нём всё, что не надо делать в проде: образ на два гигабайта вместе с компилятором и
исходниками, отладочная сборка, работа от root, запуск через оболочку (сервис не получает SIGTERM и умирает от SIGKILL через десять секунд), пароль от базы запечён в слой, а любая
правка кода пересобирает все зависимости с нуля. Рядом лежит `docker-compose.yml`, где контейнеры запускаются «как придётся», раньше, чем поднялся NATS, и наружу торчат все порты. Твоя часть:
привести оба файла и `.dockerignore` в порядок. Docker запускать не нужно: проверки читают файлы и ловят каждую из перечисленных ошибок.

## Как устроено

```
Dockerfile              образ сервиса: этап сборки и рабочий образ
docker-compose.yml      связка: nats, post-service, api-gateway
.dockerignore           что не отправлять в контекст сборки
crates/dockercheck/     проверки (tests/files.rs), править нельзя
```

- Сервис собирается из `ms/post-service`, healthcheck из `tools/healthcheck` (бинарь из задачи `svdep5`), обе цели через `cargo build --release -p ...`.
- Порт сервиса 8080, готовность отдаёт `GET /ready`.

## Что сделать

`Dockerfile`:

1. Два этапа: сборочный (именованный) и рабочий на лёгком базовом образе. В рабочий образ копируются только готовые бинарники из `target/release`.
2. Кэш зависимостей: сначала манифесты, затем сборка зависимостей (по заглушке `main.rs`), и только потом настоящие исходники и вторая сборка.
3. Только `--release`.
4. Сервис работает от непривилегированного пользователя; команда запуска в exec-форме.
5. `HEALTHCHECK` вызывает собственный бинарь `healthcheck`, без `curl`, с интервалом и таймаутом; `EXPOSE` с портом.
6. Никаких секретов в образе: ни `COPY .env`, ни `ENV ...PASSWORD...`.

`docker-compose.yml`:

1. У каждого сервиса `healthcheck`; `post-service` ждёт `nats`, а `api-gateway` ждёт `post-service` по условию `service_healthy`.
2. Пароль базы передаётся через файл-секрет: `DATABASE_PASSWORD_FILE=/run/secrets/db_password`, секрет объявлен в разделе `secrets` с файлом.
3. Наружу открыт только `api-gateway`. У всех `restart: unless-stopped`.

`.dockerignore`: `target`, `.git`, `.env` как минимум.

После работы `cargo test --workspace` проходит.

## Критерии приёмки

- образ собирается в этапы, рабочий не содержит компилятора и сборки, копируются именно бинарники;
- слои устроены так, что правка кода не пересобирает зависимости;
- сборка release, пользователь не root, `CMD` в exec-форме, `HEALTHCHECK` без curl;
- в образе, compose и `.dockerignore` нет секретов, пароль идёт файлом;
- готовность связки определяется здоровьем, а не запуском контейнеров, наружу смотрит один сервис.

## Подсказки

Тебе помогут `svdep5` (healthcheck), `svdep6` (секреты из файлов) и `svdep2` (порядок запуска по готовности): те же идеи, только в декларативной записи. Образцы инструкций ищи в документации Docker
по multi-stage builds и по `depends_on` с условиями.
