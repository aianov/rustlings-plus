# Store-слой чата на Scylla

Пора собрать всё из главы в настоящий слой хранения, который сервис чата сможет использовать как есть. Одна сессия на сервис, подготовленные запросы, отправка в несколько таблиц, история с курсором «загрузить ещё» и список чатов, отсортированный по последней активности.

## Что уже есть

`src/lib.rs`:

- типы `Message`, `Page`, `ChatSummary`;
- `StoreError` и перевод `QueryError` в него (`From<QueryError>`, как в задаче про ошибки), плюс вариант `BadCursor`;
- `encode_cursor` и `decode_cursor` (как в задаче про курсор).

Тесты лежат в `tests/store.rs` и сами создают и удаляют свой keyspace. Править их нельзя.

## Что сделать

`MessageStore` хранит `Arc<Session>` и подготовленные запросы. Имя keyspace приходит в `new` и пишется в каждом запросе (`keyspace.table`): сессия на keyspace не переключена.

1. `new(session, keyspace)`:
   - создаёт таблицы, если их нет, и ждёт согласования схемы:
     - `messages (chat_id int, sent_at bigint, id uuid, author int, body text)`: история чата, свежие первыми, сообщения одной миллисекунды не затирают друг друга;
     - `chats_by_user (user_id int, last_at bigint, chat_id int)`: чаты пользователя по последней активности, каждый чат один раз;
     - `chat_activity (user_id int, chat_id int, last_at bigint)`: последняя активность пары «пользователь, чат», чтобы знать, какую строку `chats_by_user` удалять;
   - готовит все запросы один раз, с QUORUM; все они идемпотентны (ключи готовые, счётчиков нет). Вызвать `new` повторно на том же keyspace можно.
2. `send(chat, author, body, members, at_ms)`: записывает сообщение с новым `Uuid::new_v4()` и возвращает его id, затем обновляет активность чата у каждого участника из `members` и у автора (даже если его нет в списке). Активность только растёт: опоздавшее сообщение со временем меньше текущего не двигает чат вниз. Участников обновляй параллельно.
3. `history(chat, cursor, limit)`: одна страница истории размером `limit`, свежие первыми, и курсор следующей страницы (`None`, если больше ничего нет). Испорченный курсор это `Err(BadCursor)`, а не паника.
4. `chats(user)`: чаты пользователя, свежая активность сверху.

## Критерии приёмки

`cargo test` в папке проекта при запущенной Scylla курса (`docker compose up -d`):

- история свежими вперёд, два сообщения одной миллисекунды на месте;
- 25 сообщений по 10 это страницы 10, 10 и 5 без повторов и пропусков;
- каждый чат в списке один раз, по убыванию активности, опоздавшее сообщение не двигает чат назад;
- автор вне списка участников видит чат;
- один `MessageStore` в `Arc` выдерживает 20 параллельных отправок.

`cargo clippy --all-targets -- -D warnings` без предупреждений.
