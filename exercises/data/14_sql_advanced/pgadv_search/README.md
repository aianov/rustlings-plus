# Поиск по соцсети

Лента растёт, и пользователи хотят искать: посты по словам («котики -собака», «rust or go», фраза в кавычках) и людей по
нику, даже когда ник набран с опечаткой. Пока поиск делается через `ILIKE` и читает всю таблицу, а находит только
точные подстроки. Нужна библиотека `search_kit`, которую сервис вызывает из обработчиков: схема поиска в базе и
две функции.

## Что уже есть

- `src/lib.rs`: типы и сигнатуры, константа `SCHEMA` с содержимым `src/schema.sql`. Сигнатуры менять нельзя.
- `src/schema.sql`: заготовка, в ней только комментарий.
- `tests/acceptance.rs`: приёмочные тесты. Каждый тест создаёт свою схему в Postgres курса (`RUSTLINGS_PG_URL`),
  в ней таблицы `users (id, username)` и `posts (id, title, body)`, ставит расширение `pg_trgm` (если его ещё нет),
  выполняет твой `SCHEMA` и только потом заливает данные. Схему тест удаляет в конце.

## Что нужно сделать

1. `src/schema.sql`: скрипт, который добавляет в `posts` столбец `search` типа `tsvector`, вычисляемый базой при
   каждой записи (generated, stored) из заголовка с весом A и текста с весом B на конфигурации `russian`, и GIN-индекс
   на нём; и триграммный индекс (GIN или GiST) на `users.username`. Скрипт запускается один раз на пустых таблицах.
2. `search_posts(pool, query, limit)`: посты, подходящие под запрос в формате веб-поиска (`websearch_to_tsquery`,
   конфигурация `russian`), сначала самые релевантные (ранг по `search`), при равенстве по возрастанию id, не больше
   `limit` штук. Для каждого поста вернуть `snippet`: выдержка из текста не длиннее 12 слов, найденные слова обёрнуты
   в `<mark>` и `</mark>`. Выдержка идёт на страницу как HTML, поэтому символы `&`, `<`, `>` в тексте поста
   заменяются на сущности до выделения: кроме `<mark>` и `</mark>` в выдержке не должно быть ни одного `<`.
   Пустой или состоящий из пробелов запрос даёт пустой список, а не ошибку.
3. `find_people(pool, nick)`: до пяти ников, похожих на `nick` (оператор «похоже» из `pg_trgm`), сначала самые
   похожие, при равенстве по алфавиту. Регистр не важен.

## Критерии приёмки

`cargo test` в корне проекта: все тесты из `tests/acceptance.rs` проходят. Они проверяют форму схемы (вычисляемый
столбец, виды индексов), синтаксис запроса, ранжирование по весам, выдержки и их экранирование, нечёткий поиск людей
и то, что редкое слово находится через индекс, а не перебором таблицы.

## Структура

```
pgadv_search/
  Cargo.toml
  src/lib.rs          функции и типы (твоя работа)
  src/schema.sql      схема поиска (твоя работа)
  tests/acceptance.rs приёмочные тесты (не менять)
```

## Как запускать

Postgres курса должен работать (`docker compose up -d` в папке курса). Потом `cargo test`.

## Подсказки по теории

Всё есть в README главы: `to_tsvector` и `websearch_to_tsquery` с одинаковой конфигурацией, generated-столбец с
`setweight`, GIN по `tsvector`, `ts_rank` и `ts_headline`, оператор `%` и `similarity`, класс операторов `gin_trgm_ops`.
