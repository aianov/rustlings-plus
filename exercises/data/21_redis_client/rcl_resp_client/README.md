# Клиент Redis: крейт resp-client

Соцсеть растёт: счётчики просмотров, кто недавно смотрел профиль, популярные теги, потом лимиты и кэш. Всё это
живёт в Redis, и каждому сервису нужен клиент. Готовые крейты есть, но курс как раз про то, как они устроены: ты
собираешь свой клиент из всего, что было в главе, и в вехе подключаешь его к сервисам.

## Что уже есть

- `src/lib.rs`: типы `Value`, `Error`, `Options` (со значениями по умолчанию), псевдоним `Result`. Менять не нужно.
- `src/codec.rs`: заготовки `encode_command` и `decode` с `todo!()`. Кодек из главы про RESP: пределы, неполные кадры.
- `src/client.rs`: заготовка `Client` со всеми публичными методами и `todo!()`. Внутренности придумай сам.
- `tests/acceptance.rs`: приёмочные тесты (не менять). Они ходят в Redis курса (`RUSTLINGS_REDIS_URL`, по умолчанию
  `127.0.0.1:56379`) и в свой маленький сервер на `127.0.0.1:0`, которым воспроизводятся сбои.

## Что нужно сделать

1. `Client::connect(url)` и `connect_with(url, options)`. Адрес `redis://[имя]:[пароль]@хост[:порт][/база]`, пароль
   может быть закодирован через `%XX`. Неверный адрес это `Error::InvalidUrl` до всякого подключения. При каждом
   подключении (и первом, и после обрыва) идут `AUTH` (если есть пароль), `SELECT` (если база не 0) и `PING`.
   Всё подключение укладывается в `connect_timeout`, иначе `Error::Timeout`.
2. Один клиент, много задач: `Client` клонируется, все копии делят одно соединение. Команды уходят в сокет по мере
   поступления (pipelining), ответы раздаются в порядке команд. Одновременно в полёте не больше `max_in_flight`.
   Когда исчезла последняя копия, соединение закрывается.
3. `call(&[...])` возвращает `Value`. Ответ-ошибка сервера это `Error::Server { kind, message }`. На всю команду есть
   `command_timeout`, срок это `Error::Timeout`, и он не должен портить соединение: следующая команда получает свой
   ответ.
4. `pipeline(&[...])` отправляет пачку и возвращает ответы по порядку. Ошибка одной команды остаётся значением
   `Value::Error` в списке.
5. Типизированные команды: `get`, `set`, `set_ex`, `del`, `incr`, `expire`, `ttl`. Ответ неожиданного вида это
   `Error::Unexpected(Value)`.
6. Обрыв соединения: запросы, которые уже ушли в него, получают `Error::Disconnected` (повторять нельзя: неизвестно,
   выполнены ли они). Клиент подключается заново с паузой `reconnect_pause`, а запросы, которые ещё не отправлены,
   ждут нового соединения.
7. Нарушение протокола (в том числе заголовок длиннее `max_bulk`, обнаруженный по самому заголовку) это
   `Error::Protocol(причина)` для ожидающих, соединение закрывается и открывается заново.
8. `blpop(ключ, секунды)` ждёт на отдельном соединении, которое открывается на вызов и закрывается после: общее
   соединение остаётся свободным.

## Критерии приёмки

`cargo test` в корне проекта: все тесты из `tests/acceptance.rs` проходят. Они проверяют адрес и вход, срок
подключения, типизированные команды и ошибки, порядок и изоляцию ошибок в пачке, пятьдесят задач на одном клиенте,
таймаут без рассинхронизации, обрыв и переподключение, нарушение протокола, блокирующую команду, ограничение
числа команд в полёте и закрытие соединения.

## Структура

```
rcl_resp_client/
  Cargo.toml
  src/lib.rs          типы и ошибки (готово)
  src/codec.rs        кодек (твоя работа)
  src/client.rs       клиент (твоя работа)
  tests/acceptance.rs приёмочные тесты (не менять)
```

## Как запускать

Redis курса должен работать (`docker compose up -d` в папке курса). Потом `cargo test`. Для первой сборки понадобится
сеть к реестру крейтов. Ничего, кроме `tokio` и `bytes`, подключать не нужно (и крейт `redis` брать нельзя: это
весь смысл).
