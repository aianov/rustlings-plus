# Оконные функции

Начальнику нужен список продаж менеджеров, и рядом с каждой продажей хочется видеть, какая она по
счёту у этого менеджера, какое место занимает по сумме и сколько набралось нарастающим итогом.
`GROUP BY` тут не помогает: он схлопывает строки в одну на группу, а список нужен целиком, строка
за строкой. Для такого в SQL есть оконные функции. Они считают значение по группе соседних строк
и пишут его рядом с каждой строкой, ничего не схлопывая.

Примеры в тексте про продажи (`sales`), в задачах соцсеть.

```
sales
 id | rep   | amount | sold_on
  1 | Анна  |   300  | 03-01
  2 | Борис |   500  | 03-01
  3 | Анна  |   500  | 03-02
  4 | Борис |   200  | 03-03
```

## Анатомия: функция OVER (окно)

```sql
SELECT id, rep, amount,
       sum(amount) OVER (PARTITION BY rep ORDER BY sold_on) AS running
FROM sales
```

Всё, что после `OVER`, описывает окно для текущей строки.

- `PARTITION BY rep` делит строки на независимые разделы (по менеджерам). Без него раздел один,
  вся таблица.
- `ORDER BY sold_on` задаёт порядок строк внутри раздела. Без него порядок не определён: нумерация
  выйдет произвольной, а «предыдущая строка» потеряет смысл.
- Рамка (frame), о ней ниже, выбирает из раздела те строки, которые функция видит для текущей.

Результат: столько же строк, сколько на входе, плюс новый столбец. Ты можешь писать в одном запросе
сколько угодно окон с разными OVER. Если одно и то же окно нужно в нескольких местах, его называют:

```sql
SELECT id, lag(amount) OVER w, lead(amount) OVER w
FROM sales
WINDOW w AS (PARTITION BY rep ORDER BY sold_on)
```

**Окно против GROUP BY.** `count(*) ... GROUP BY rep` вернёт строку на менеджера. `count(*) OVER
(PARTITION BY rep)` вернёт все строки продаж, и в каждой будет число продаж менеджера. Первое сворачивает,
второе добавляет столбец.

## Когда окна вычисляются

Порядок выполнения запроса: `FROM`, `WHERE`, `GROUP BY`, `HAVING`, **окна**, `SELECT` (выражения),
`ORDER BY`, `LIMIT`. Из этого два следствия.

1. В `WHERE`, `GROUP BY` и `HAVING` оконной функции быть не может: к моменту WHERE номера ещё нет.
   Нужно фильтровать по результату окна, оберни запрос в подзапрос или `WITH` и фильтруй снаружи.
2. Окно видит результат `GROUP BY`, а значит, можно писать окно поверх агрегата. Доля менеджера в общем
   числе продаж:

   ```sql
   SELECT rep, count(*) AS n,
          round(100.0 * count(*) / sum(count(*)) OVER (), 1) AS share
   FROM sales GROUP BY rep
   ```

   Внутренний `count(*)` считается группой, внешний `sum ... OVER ()` складывает уже посчитанные группы.
   Если добавить `ORDER BY` в окно, сумма станет нарастающей.

## Агрегат по всему разделу

Окном может быть любой агрегат, и без `ORDER BY` он считается по всему разделу сразу. Так в одной строке рядом
оказываются «моё значение» и «значение раздела»:

```sql
SELECT rep, amount,
       max(amount) OVER (PARTITION BY rep)              AS best_of_rep,
       max(amount) OVER (PARTITION BY rep) - amount     AS behind_best
FROM sales
```

`behind_best` это отставание от лучшей продажи своего менеджера. Тот же приём даёт долю от суммы
(`amount / sum(amount) OVER ()`) и отклонение от среднего (`amount - avg(amount) OVER (PARTITION BY rep)`).

## Нумерация и места

```sql
SELECT rep, amount,
       row_number() OVER (ORDER BY amount DESC) AS n,
       rank()       OVER (ORDER BY amount DESC) AS place,
       dense_rank() OVER (ORDER BY amount DESC) AS dense_place
FROM sales
```

Для сумм 500, 500, 300, 200 функции вернут:

| сумма | row_number | rank | dense_rank |
|---|---|---|---|
| 500 | 1 | 1 | 1 |
| 500 | 2 | 1 | 1 |
| 300 | 3 | 3 | 2 |
| 200 | 4 | 4 | 3 |

`row_number` раздаёт уникальные номера, при равных ключах порядок среди равных не определён (добавь
второй ключ сортировки, если нужна воспроизводимость). `rank` выдаёт равным одно место и пропускает
следующие (как в спорте: два первых места, второго нет). `dense_rank` равным даёт одно место и не
пропускает.

«Два лучших в группе» делаются номером в разделе и фильтром снаружи:

```sql
SELECT * FROM (
    SELECT s.*, row_number() OVER (PARTITION BY rep ORDER BY amount DESC, id) AS rn
    FROM sales s
) t
WHERE rn <= 2
```

Фильтровать нужно снаружи, потому что в `WHERE` того же запроса номера ещё нет. Для «лучшего одного» `rn = 1`.

### DISTINCT ON: короткая форма для «одна строка на группу»

Postgres умеет то же короче:

```sql
SELECT DISTINCT ON (rep) rep, id, amount
FROM sales
ORDER BY rep, amount DESC, id
```

Из каждой группы остаётся первая строка по `ORDER BY`. Выражения в `DISTINCT ON` должны совпадать
с началом `ORDER BY`, иначе ошибка: порядок внутри группы иначе не определён. Это расширение Postgres,
не стандарт SQL. Для «первых N на группу» подходит окно с `rn <= N` или `LATERAL` из прошлой главы.

## Соседи: lag и lead

```sql
SELECT id, rep, amount,
       lag(amount)  OVER (PARTITION BY rep ORDER BY sold_on) AS prev_amount,
       lead(amount) OVER (PARTITION BY rep ORDER BY sold_on) AS next_amount
FROM sales
```

`lag` берёт значение из предыдущей строки раздела, `lead` из следующей. У границы раздела получается NULL
(можно подставить значение вторым и третьим аргументом: `lag(amount, 1, 0)`). Разница с соседом
`amount - lag(amount) OVER (...)` даёт «рост к прошлому разу». У первой строки она NULL, не ноль. Разница двух
моментов времени имеет тип `interval`; чтобы получить число часов, берут `extract(epoch FROM разница) / 3600`
(секунды делят на 3600), а `round(число)` округляет.

## Рамка: ROWS и RANGE

Агрегат в окне (`sum`, `avg`, `count`) считает по рамке, то есть по части раздела вокруг текущей
строки. Если в `OVER` есть `ORDER BY`, рамка по умолчанию такая:

```
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW   -- от начала раздела до текущей, включая равных ей
```

Слово «равных» важно. `RANGE` смотрит на значения ключа, а не на положение строки: все строки с тем же
значением в `ORDER BY` считаются «текущей» одновременно. Поэтому нарастающий итог по неуникальному ключу
скачет:

```
дата    сумма   RANGE (по умолчанию)   ROWS
03-01    300           800                  300
03-01    500           800                  800
03-02    500          1300                 1300

RANGE = sum(...) OVER (ORDER BY дата)
ROWS  = sum(...) OVER (ORDER BY дата ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
```

Нужен честный нарастающий итог строка за строкой, пиши рамку явно: `ROWS BETWEEN UNBOUNDED PRECEDING AND
CURRENT ROW`, либо добавь в `ORDER BY` уникальный ключ. Для скользящего среднего берут окно по строкам:
`avg(x) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` усредняет текущую и шесть
предыдущих строк, а в начале раздела рамка короче. Посмотри `visuals/window_frame.html`: там видно, какие
строки попадают в рамку в каждом режиме.

Функции нумерации и `lag`/`lead` рамку не используют, она влияет только на агрегаты и на `first_value`,
`last_value`, `nth_value`.

## Типичные ошибки

- Оконная функция в `WHERE`: «window functions are not allowed in WHERE». Оберни в подзапрос.
- Нарастающий итог по неуникальному ключу без явной рамки: равные строки получают одинаковое число.
- `row_number` там, где нужна ничья: двум равным результатам достались разные места.
- `lag` без `PARTITION BY`: «предыдущей» оказалась строка другой группы.
- `DISTINCT ON` с `ORDER BY`, который не начинается с ключа группы.
- Ждать от `last_value` последнего значения раздела: при рамке по умолчанию это просто текущая строка.
- Забыть второй ключ в `ORDER BY` окна: результат меняется от запуска к запуску.
