# ntx_server_interceptor: кто звонит

Сервис постов должен знать, от какого пользователя пришёл вызов, и не пускать анонимов. Проверять токен в начале каждого обработчика
значит забыть это в новом. **Перехватчик сервера** делает проверку один раз для всего сервиса: до обработчика, и кладёт найденного
пользователя в `extensions` запроса, откуда обработчик его достаёт.

## Что сделать

В `src/lib.rs`:

1. `Auth::call` (перехватчик): читает `authorization: Bearer <токен>`, по таблице токенов находит номер пользователя и кладёт
   `UserId` в `request.extensions_mut()`. Любая беда (нет заголовка, не тот формат, не ASCII, неизвестный токен) это `Unauthenticated`.
   В тексте ошибки токена быть не должно: логи ошибок читают многие.
2. `start(auth, calls)`: поднимает один сервер с двумя сервисами. `Me` (метод `WhoAmI`, отвечает номером вызвавшего) закрыт перехватчиком,
   `Public` (метод `Ping`) открыт всем: перехватчик не видит имени метода, и открытые методы живут в отдельном сервисе.

Обработчик `WhoAmI` уже написан. Он берёт `UserId` из расширений и считает свои вызовы в `calls`: так тесты увидят, был ли
обработчик вызван.

## Критерии приёмки

`cargo test`: верный токен даёт номер пользователя; без заголовка, с чужой схемой, с неизвестным токеном, с нечитаемым значением
вызов кончается `Unauthenticated`, обработчик не вызывался и токен в сообщении не повторён; `Ping` работает без токена.

## Подсказки по теории

`InterceptedService` оборачивает один сервис. Генерируемая обёртка даёт короткий путь: `MeServer::with_interceptor(svc, interceptor)`.
`add_service` можно вызывать несколько раз, перехватчик действует только на тот сервис, который им обёрнут.
