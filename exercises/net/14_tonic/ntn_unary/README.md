# ntn_unary: первый настоящий сервер

Схема и сборка готовы. Осталось научить сервис отвечать: хранить пользователей в памяти, выдавать их по номеру, создавать новых и
запускаться на свободном порту так, чтобы тесты и другие сервисы знали, куда стучаться.

## Что сделать

В `src/lib.rs`:

1. `get_user`: пользователь с таким номером или `Status::not_found` (подробнее про коды в следующих задачах).
2. `create_user`: выдаёт следующий номер (первому пользователю 1, дальше по порядку без повторов), сохраняет и возвращает
   созданного. Вызываться он будет из многих задач сразу.
3. `start(svc)`: привязывается к `127.0.0.1:0`, **до возврата** отдаёт готовый к соединениям адрес и запускает сервер в фоновой
   задаче. Возвращает адрес и `JoinHandle` этой задачи. Остановка сервера это `handle.abort()`.

## Критерии приёмки

`cargo test`: обработчики работают при прямом вызове без сети; через настоящего клиента по сети; сорок параллельных
`create_user` дают сорок разных номеров; два сервера живут на разных портах и не делят пользователей; к адресу можно подключиться
сразу после `start`; после `abort` порт закрыт.

## Подсказки по теории

`Server::builder().add_service(UsersServer::new(svc))` собирает роутер, а `serve_with_incoming(TcpListenerStream::new(listener))`
запускает его на уже открытом слушателе. Так порт известен заранее, в отличие от `serve(addr)`, который открывает порт внутри
и ничего о нём не сообщает.
