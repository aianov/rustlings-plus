# ntn_build: от .proto до сервиса

Первая задача главы: собрать фундамент. Сервис пользователей соцсети пока умеет одно, отдавать пользователя по номеру, но
контракт должен лежать в `.proto`, а Rust-код получаться из него при сборке. Ты напишешь схему, `build.rs` и подключение
сгенерированного кода. Реализовывать сервис пока не нужно: его напишут тесты, чтобы проверить, что сгенерировалось то, что надо.

## Что уже есть

`Cargo.toml` с зависимостями `tonic`, `tonic-prost`, `prost`, `tokio` и `tokio-stream` и сборочной зависимостью
`tonic-prost-build`, а ещё приёмочные тесты. Для сборки нужен `protoc` (`protoc --version`; на macOS `brew install protobuf`).

## Что сделать

1. `proto/users/v1/users.proto`: пакет `users.v1`, сервис `Users` с **одним** методом `GetUser`.

   | сообщение | поля |
   |-----------|------|
   | `GetUserRequest` | `uint64 id = 1` |
   | `User` | `uint64 id = 1`, `string handle = 2`, `string display_name = 3` |

2. `build.rs`: собирает схему через `tonic_prost_build` и сообщает cargo, когда запускаться заново.
3. `src/lib.rs`: подключает сгенерированный код так, чтобы пути выглядели как `ntn_build::users::v1::User`
   и `ntn_build::users::v1::users_server::UsersServer`.

## Критерии приёмки

`cargo test`:

- имя сервиса на проводе ровно `users.v1.Users` (по нему клиент строит путь `/users.v1.Users/GetUser`);
- в сервисе один метод: тест реализует трейт только с `get_user`, лишний метод в схеме не даст ему собраться;
- сообщение `User` кодируется в согласованные байты;
- сервер, написанный в тесте, отвечает настоящему клиенту по сети, а ещё трейт можно вызвать напрямую, без сети;
- в `build.rs` есть `cargo:rerun-if-changed`.

## Структура

```
ntn_build/
  Cargo.toml          готово
  build.rs            твой
  proto/users/v1/     твой
  src/lib.rs          твой
  tests/acceptance.rs
```

## Подсказки по теории

Сгенерированный файл называется по пакету (`users.v1.rs`) и лежит в `OUT_DIR`. Макрос `tonic::include_proto!("users.v1")`
подключает его по имени пакета. Модули вокруг макроса должны повторять пакет: так делают и все остальные проекты главы.
