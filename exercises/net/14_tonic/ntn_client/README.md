# ntn_client: канал до сервиса

Шлюз соцсети ходит в сервис пользователей десятки раз в секунду. Чтобы это было дёшево, у шлюза должен быть один `Channel` на сервис,
созданный при старте и без лишних церемоний. Сервис может быть ещё не поднят в момент старта шлюза, а зависший сервис не должен
подвешивать шлюз: вызову нужен срок.

## Что сделать

В `src/lib.rs` функция `make_channel(addr, connect_timeout, request_timeout)` строит `Channel` до сервиса:

1. функция **синхронная**: она не ждёт, пока сервис ответит, и не падает, если сервис ещё не запущен;
2. на подключение отведён `connect_timeout`, на каждый вызов `request_timeout`.

`handle_of(channel, id)` готов: он берёт клиента из канала и спрашивает имя пользователя.

## Критерии приёмки

`cargo test`: канал создаётся для адреса, где никто не слушает, мгновенно; вызов в пустоту быстро кончается `Unavailable`;
медленный обработчик обрывается по `request_timeout`, а быстрый отвечает; канал, созданный до запуска сервера, сам подключается,
когда сервер появился.

## Подсказки по теории

`Endpoint` описывает, куда и как ходить, а `Channel` это уже готовое (или лениво подключаемое) соединение. Клиент `UsersClient<Channel>`
дёшево клонируется, и все клоны делят одно HTTP/2-соединение.
