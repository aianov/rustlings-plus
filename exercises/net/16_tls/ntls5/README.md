# ntls5: что видит тот, кто слушает провод

Всё, что идёт по сети без шифрования, читает любой, через чьи руки оно проходит: Wi-Fi в кафе, провайдер, сосед по стойке, «прокси для отладки», который забыли выключить. Лучший способ понять, что даёт TLS и чего не даёт, поставить такого слушателя самому.
В проекте уже есть `Tap`: прозрачный посредник между клиентом и сервером, который записывает все байты в обе стороны. Тесты проводят через него вход по паролю по обычному TCP и по TLS и смотрят, что осело в записи.

## Что сделать

Допиши в `src/lib.rs` три функции для разбора записи:

1. `contains(hay, needle)`: есть ли `needle` как подпоследовательность байтов в `hay`. Пустая иголка найдена всегда.
2. `looks_like_tls(bytes)`: начало записи похоже на TLS-запись (тип 22 «рукопожатие» и версия `3.x` в заголовке записи).
3. `sni(bytes)`: имя сервера из расширения `server_name` в ClientHello, если оно есть. Оно идёт в открытом виде даже в TLS 1.3: тот, кто слушает, видит, **к какому** хосту ты идёшь, хотя не видит, **о чём** идёт разговор.
   Входные данные могут быть чем угодно: оборванным ClientHello, обычным HTTP, мусором. Функция не должна паниковать ни на каком входе и не должна возвращать неверное имя на обрезанном входе.

## Критерии приёмки

`cargo test`: пароль виден в записи обычного TCP и не виден ни в одну сторону в записи TLS; запись TLS узнаётся по заголовку; имя `localhost` читается из ClientHello, а при подключении по IP его нет; на каждом обрезанном префиксе настоящего ClientHello разбор либо не находит имя, либо находит правильное, но никогда не паникует.

## Подсказки по теории

ClientHello устроен так: запись (1 байт тип, 2 байта версия, 2 байта длина), внутри неё сообщение рукопожатия (1 байт тип `1`, 3 байта длина, 2 байта версия, 32 байта случайных данных), потом идут поля переменной длины с префиксом длины:
идентификатор сессии (1 байт длины), наборы шифров (2 байта длины), методы сжатия (1 байт длины), расширения (2 байта общей длины). Каждое расширение это 2 байта типа, 2 байта длины и данные. Тип `0` это `server_name`:
список (2 байта длины), в нём запись «тип имени 0, 2 байта длины, имя». Все числа в сети идут от старшего байта к младшему.
