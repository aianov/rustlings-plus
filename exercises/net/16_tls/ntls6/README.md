# ntls6: почему рукопожатие не удалось

В журнале сервиса: `handshake failed: invalid peer certificate`. А причин у этого может быть пять: сертификат выдал чужой CA, он выдан на другое имя, срок прошёл, срок ещё не наступил, или это вообще не про сертификаты. Каждая лечится по-своему
(подложить нужный CA, поправить SAN, перевыпустить, поправить часы на сервере), и без точной причины дежурный выбирает наугад.

## Что сделать

В `src/lib.rs` перечисление `VerifyFailure` и функция `try_connect` (клиент проверяет сертификат сервера) уже есть. Допиши:

1. `classify(err)`: по `io::Error` из рукопожатия определяет причину. Ошибки TLS лежат внутри `io::Error` (смотри `get_ref()` и `downcast_ref`). Всё, что не про проверку сертификата (обрыв, чужой протокол), это `Other` с текстом.
2. `describe(failure)`: строка для журнала. Для разных причин разная, понятная человеку, с подсказкой, что делать.

## Критерии приёмки

`cargo test`: настоящие рукопожатия с сертификатом чужого CA, с сертификатом на другое имя, истёкшим, ещё не вступившим в силу; сервер, который просто закрывает соединение; не-TLS сервер; описания всех причин различны и непусты.

## Подсказки по теории

Рукопожатие, которое отвергло сертификат, возвращает `io::Error`, в котором лежит `rustls::Error::InvalidCertificate(CertificateError::...)`. Перечисление `CertificateError` не закрыто: в новых версиях часть вариантов (например «истёк») появляется
в двух видах, с подробностями и без. Ловить нужно оба.
